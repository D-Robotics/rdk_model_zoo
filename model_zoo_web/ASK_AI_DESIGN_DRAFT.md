# Model Zoo Ask AI 设计初稿

状态：讨论稿。本文描述产品与交互方案，不代表现有功能或发布承诺。

## 1. 目标与边界

Ask AI 帮用户完成三件事：按目标板卡找到已发布模型；理解模型的运行方式、精度和性能；在目录缺少合适模型时提交需求并追踪处理进度。对话中的模型事实必须指向可核查的 Catalog、Sample 文档或发布报告。

这里有两类不同的提交：

| 类型 | 用户提交什么 | 结果 |
| --- | --- | --- |
| 申请收录公开模型 | 官方模型链接、任务、目标板卡和用途 | 一条可追踪的收录需求；是否适配与发布由维护者决定 |
| 编译自有模型 | 私有模型文件、输入合同、校准与评测资料 | 私有编译任务与候选制品；公开收录另需授权和发布审核 |

网站目录目前由审核后的 `model_zoo_web/data/` 生成，经 `web-v*` 标签部署到 GitHub Pages；网页仍保持静态。对话、表单、任务状态由单独的 API 服务提供。编译服务不直接暴露给浏览器。

## 2. 视觉方向

沿用全站统一的 Apple 式产品界面语言，并保留 D-Robotics 品牌与技术目录的内容密度：

| 元素 | 现有样式 | Ask AI 延续方式 |
| --- | --- | --- |
| 页面 | 浅灰画布、白色内容面、深灰文字 | 对话面板使用白底工作区，靠留白和细分隔线分区 |
| 强调色 | `#0071e3` | 仅用于主操作、链接、焦点和当前状态 |
| 文字 | 系统无衬线；文件名和命令用等宽字 | 回复正文 14px，证据与状态 12-13px，代码等宽 |
| 控件 | 约 40-44px 高、最多 8px 圆角 | 输入框、按钮、选择器保持同样尺度 |
| 图标 | `public/assets/icons/` 的简洁线性图标 | 入口使用现有 `sparkles.svg`；关闭、外链复用现有图标 |

回答不用彩色聊天气泡或大面积渐变。用户问题以浅灰底单行/多行块显示，助手回答用正文、表格和带来源的链接。模型推荐以紧凑列表行呈现，避免在面板里嵌套模型卡片。

## 3. 入口与布局

1. 顶部导航在 `GitHub` 前增加带星光图标的 `Ask AI` 入口，所有页面可见。它是明确的工具按钮，不使用遮挡内容的悬浮按钮。
2. 模型详情页在“获取模型”旁增加次级操作“询问此模型”。打开时自动带入模型 ID、平台、变体和当前页面链接。
3. 搜索无结果时保留“清除筛选”，另提供“询问 Ask AI”和“申请收录”。只有确认 Catalog 没有匹配项后，才引导提交需求。
4. 桌面宽屏（建议 >=1280px）打开右侧约 416px 面板，目录改为两列卡片，左侧筛选仍可用。较窄桌面使用右侧覆盖抽屉；手机使用整屏对话视图，关闭后返回原来的滚动位置。

```text
桌面宽屏
┌ 顶部：RDK Model Zoo                   Ask AI  GitHub  EN/中文 ┐
├ 筛选栏 ┆ 模型目录 / 模型详情         ┆ Ask AI              ┤
│        ┆                              ┆ 对话与来源链接       │
│        ┆ 模型卡片或性能报告           ┆ 模型相关问题提示     │
│        ┆                              ┆ 输入框 / 发送         │
└─────────────────────────────────────────────────────────────┘

手机：目录与 Ask AI 分别占满视口；顶部返回键切换，输入框固定在安全区域上方。
```

面板顶部只保留标题和关闭按钮。空白态以对话式问候和自然语言问题开场；提交模型需求先进入对话，再由回复引导到表单，不设置底部操作栏。从详情页的“询问此模型”进入时自动带入当前模型；从顶部 Ask AI 进入时使用整个已发布目录。对话记录在目录和详情页切换时保留；切换语言时界面文案同步变化，不翻译用户已有的问题。

## 4. 对话内容与操作

初始可选问题从真实 Catalog 动态生成，例如“查找 S600 检测模型”“比较 X5 与 S600 的已发布变体”；当前模型页显示“查看精度依据”“获取运行命令”。没有对应数据时不展示该快捷问题。

一次回答尽量按以下顺序：直接结论、匹配模型或步骤、证据链接、下一步操作。涉及数值时显示板卡、模型变体、指标口径和来源；例如 Runtime 延迟不能写成端到端延迟。推荐结果行点击后打开现有详情页，下载仍交给现有“获取模型”流程。

```text
Ask AI                                   当前：YOLO26 Detect / S600
你：这个模型的精度数据从哪里来？

答：页面列出 COCO val2017 的浮点参考和板端结果。
    两者属于不同运行阶段；点击指标可查看测试条件。
    来源：模型详情 / 评测说明 / 发布报告
    [查看精度]  [查看转换报告]

输入问题...                                                [发送]
```

检索结果区分三种状态：

- **Web 已发布**：以当前 Catalog 记录为准，提供详情、下载和报告链接。
- **Sample/历史清单有记录，Web 未收录**：准确说明来源和状态，不显示伪造的网页下载入口。
- **没有足够证据**：说明尚未找到可核查记录，提供“提交模型需求”；不推断硬件一定不支持。

提问含糊时只追问影响结论的字段，优先是目标板卡和模型任务。模型信息、性能数字与下载地址来自结构化数据；文档检索用于解释命令、限制和排错。每条关键结论显示来源链接和 Catalog 版本。对话可以预填申请表，但提交前必须让用户检查表单。

## 5. 提交表单

表单使用独立页面或全屏侧页，而不是窄聊天面板中的长表单。顶部用分段控件选择“申请收录”或“编译我的模型”，下方沿用详情页的分组字段、细边框和蓝色主按钮。

**申请收录**的必填项：模型名称、官方来源 URL、任务类型、目标板卡、用途说明、联系渠道。许可证链接、期望输入尺寸和目标指标可选；提交前检查重复需求。这个入口可以先实现为公开工单。

**编译我的模型**需登录，并提交模型文件或受控上传链接、SHA256、权利声明、目标板卡、输入/输出形状与数据类型、前后处理、校准数据、评测数据及指标。上传和任务结果默认私有。缺少评测资料时可以请求“编译可行性检查”，但不能标记为“已通过发布测试”。

提交成功后显示需求编号、当前状态、可补充资料和撤回入口。用户可以从 Ask AI 的“查看进度”操作回到任务页。

## 6. 任务页与状态

任务页用纵向步骤和简洁证据表，共同阶段为“已提交 -> 预检 -> 等待资源 -> 编译 -> 板端验证”。私有模型在验收后进入“候选制品可下载”；公开收录需求继续进入“发布审核 -> 已发布”。每一步展示实际时间、结果及可查看的摘要；失败时展示第一处失败原因与需要补充的材料。`未运行`、`未通过`、`等待审核`应清晰分开。

成功编译先生成私有候选制品和报告。只有模型许可、全量精度、板端功能、Runtime 性能、C++ 端到端测试与发布审核满足现有门槛后，才生成 Catalog 变更并进入网站发布。公开页面只展示已经审核发布的记录。

## 7. 服务边界与首版范围

```text
静态网页 -> Ask AI / 需求 API -> 检索索引、任务数据库、队列
                                      |-> 受限编译 Worker
                                      |-> 板卡测试 Worker
                                      |-> 私有候选 OSS
                                      `-> 审核后的 Catalog PR / Pages 发布
```

首版建议只交付有来源的问答、详情页上下文、公开模型收录表单与任务查询。第二阶段让现有已适配的 YOLO Detect 家族进入自动编译和私有候选测试；新模型架构仍先进行适配评审。这样可以验证用户是否真的需要对话和提交入口，同时保留当前模型发布的证据标准。

## 8. 产品决定建议

| 决定 | 初稿建议 |
| --- | --- |
| 公开模型申请入口 | 首版用 GitHub Issue Form，减少工单服务开发；私有上传必须走自有 API |
| 私有模型编译开放范围 | 先对登录的试点用户开放，并设置任务配额与文件保留期 |
| Ask AI 检索范围 | 同时索引 Web Catalog、当前 Sample 文档及历史清单；回答按“Web 已发布 / 仅 Sample 有记录 / 历史资料”标注来源 |
