# 开发交付检查表

每项填写 `done / not-run / not-applicable` 与证据；not-applicable 必须说明适用规则。不把目录存在等同功能完成。

| 检查 | 证据要求 |
|---|---|
| 用户需求与平台、任务、语言范围明确 | 需求来源与范围记录 |
| 已读目标规范并区分强制/惯例/提案 | 适用条款来源和冲突处理；含目标 ref 的 README/推理契约（若存在） |
| 改动前列出 README 契约触及面与文件职责 | 逐文件↔契约章节清单（含父级索引），不是事后补记 |
| 接口与职责完整 | Config/Model/main/run.sh 与 I/O 对照 |
| 推理三阶段职责边界（pre/forward/post/predict） | forward 无下载/NMS/解码/绘图/文件输出的契约对照或测试；多阶段任务按契约编排 |
| host 逻辑先失败后通过 | 回归用例、实际失败和通过日志 |
| 错误路径及资源释放 | 无输入、坏文件、空输出、异常 metadata/任务状态检查 |
| 公共工具复用和消费者回归 | 被影响调用方列表及选择理由 |
| Python/C++ 与任务输出符合适用合同 | 源码位置、相应测试或未运行项 |
| 注释与文档真实完整 | 公共 API 与文档的交叉检查 |
| 模型获取、路径、参数一致 | download/main/run/README/Manifest 对照；CLI 默认值与 README 表格逐项核对 |
| 改动后逐条文件↔检查证据关联 | 关联表引用真实命令/输出/评审来源；禁止"文档已更新"一行代替 |
| conversion/evaluator 可复现而非占位 | 真实入口、版本/配置、边界说明 |
| README 支持声明与全局索引、Manifest、download/CLI/构建映射一致 | 根/分类索引交叉核对结果；发布资产（task/variant/size/input/board）与运行时覆盖分开判断；variant×size 覆盖结论及来源（仅本次触及文档时） |
| 样例文档措辞为当前事实 | 用法/准备/runtime 文档无写作意图/审计过程叙述；缺失输入、null 校验和、许可证状态、SDK 约束、编译与模型绑定事实保留；替换语句有代码或清单证据 |
| 双语全文与代码块复核 | EN/CN 语义对照、无截断句、无重复段；改动前后可执行代码块比对，命令变化说明理由 |
| 根/类别索引及双语同步 | 仅在本次影响或明确要求时更新；只使用已存在索引，不新建空文档 |
| 数据与产物未误提交 | git diff 文件列表与 ignore 策略 |
| 验证范围和未完成项如实记录 | 按平台×变体×任务×runtime 的报告 |
| review 已独立完成或明确尚未完成 | reviewer、范围和 findings，不以作者自检冒充 |

修复交接附：原始症状、日志打印位置、调用/数据流、排除依据、最小改动、回归方式。无法验证的判断保留为假设。
