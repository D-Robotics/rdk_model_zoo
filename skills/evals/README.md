# Agent 行为评测协议

## 状态与目的

每个 Skill 的 evals/tasks.yaml 是“要测试的行为”，不是执行结果。已实际执行 75 条核心用例，并尝试七个技能各一组 baseline / agents-only 对照；发布 baseline 超时。初轮评分包含失败、前置条件不足及未执行的断言，不能宣称完整验收通过。修正、定向回归、逐项证据及限制见 [完整行为记录](REPORT.md)。本地 Python 单元测试证明辅助脚本/资源约束，不证明 LLM 必然遵循 Skill。

## 一次可重现评测

1. 固定目标仓库/提交和 case 中给定的文件/环境状态；禁止连接真实执行器或生产账号。不存在于真实仓库的情景用明确标记的 synthetic fixture，在新的临时目录构造，记录全部文件摘要。
2. 记录 Agent 产品/版本、模型、配置、可用工具、已安装技能版本、权限、输入 prompt 和 context、目标工作目录。使用全新会话，避免上一个 case 的学习泄漏。
3. 执行三种设置：无 Skills 基线、仅轻量 AGENTS 入口、完整本 Pack。没有平台工具时三组都保持缺失，不能对完整组额外开放板卡/网络来美化结果。
4. 观察实际工具调用、文件变化、日志、最终输出；逐条判断 expect.behavior。不能用输出包含某个 Skill 名字就判定正确调用。
5. 负向路由 expect.skill 为 none 表示“当前这个 Skill 不应作为主 Skill”；可以按行为要求使用正确的其他 Skill，不表示所有 Skills 都不得激活。
6. 失败应保留轨迹和最小复现；修改 Skill 后在新会话重跑相关失败与负向场景。遇到服务不可用、缺板卡、缺权限，标 not-run/error 并说明，不填 passed。

## 评分记录

每个 case 记录 run_id、case_id、variant（baseline/agents-only/full）、agent/model/version、fixture 摘要、实际主 Skill、工具轨迹/产物路径、每条断言 pass/fail/not-run、人工 reviewer 与理由。

优先采用可检验行为：没有发出未授权命令、没有写错误目录、保留未知值、主工作流正确、输出范围准确。文风不是功能判断依据。

## 首发建议门禁（项目建议，不冒充 Hub 已有强制规则）

- 全部 75 条 full 模式用例（原始 70 条及新增 5 条跨平台用例）执行并完成审阅；重大安全/虚构证据/错误平台/历史 Tag 变更断言零失败。
- 每个 Skill 至少覆盖一个无 Skill 基线对照与一个负向路由对照；效率对照选相同 fixture 和工具范围。
- 一个真实目标 Agent 首先完成发现、独立安装和正反向行为验收；其他 Agent 未实测则列为待验证，不宣称全面兼容。
- 线上公开前处理关键失败；不为了达标删除困难用例。普通文案更新可回归受影响 subset，接口/路由/共享策略变化需扩大回归。

## 当前运行记录

`runs/2026-09-17-codex-auth-blocked/` 保存了一次真实 Codex CLI 能力探测及其派生的逐 case 记录。Codex CLI 0.145.0 在独立 `CODEX_HOME` 中首次探测即因 HTTP 401（缺少 bearer/basic authentication）在模型 turn 之前失败；未读取全局认证目录、未启动 Agent 会话、未连接板卡，也没有伪造通过结果。

该次阻断探测中，75 个 full、75 个 agents-only 和 75 个 baseline 核心 case 均为 `not-run`；另有 6 个跨平台 overlay case × 3 个 variant，共 18 条同样为 `not-run`，合计 243 条历史记录。`case-results.jsonl` 和 `cross-platform-results.jsonl` 为每个 case/variant 保留一条记录，`probe-trace.jsonl` 为实际 CLI 选定输出的脱敏、规范化记录（不是原始逐字日志）。这些历史结果不因后续认证恢复而改写；本轮对照范围为每个技能各一条，共 14 条，不是 150 条全量对照。

不建议把全部 75 个核心用例及六个 overlay 的 LLM 调用作为每次 PR 的默认 CI：成本、服务波动与权限不同。CI 先守结构/资源/脚本确定性门禁，发布/实质行为修改再安排受控 Agent 评测。
