# Public S100 specification (2026-11-05)

`tv-b16-imagenet1k-224-featuremap-int16-cpuptq-o1-20261105` is an independently identified S100 (`nash-e`) conversion. Independent torchvision ViT-B/16 ImageNet-1K model, not the historical CIFAR-10 weights. Source PIL bilinear resize shorter256, center224; RGB /255 and ImageNet mean/std.

The [conversion registry](converted_targets_20261105.json) records the trained source/checkpoint pair, compiled artifact, actual complete ABI, original configuration, calibration manifest and receipts. The model license is preserved in this directory. Historical specifications below the sample's new public-specification link keep their original contracts and measurements.

## Prepare and execute

On dev-server or the selected board, from repository root:

```bash
python3 -m utils.py_utils.converted_featuremap --sample vit --target s100 --variant tv-b16-imagenet1k-224-featuremap-int16-cpuptq-o1-20261105 --asset-id s:vit:s100/vit_tv_b16_imagenet1k_224_featuremap_int16_cpuptq_o1_20261105_nashe.hbm
python3 -m samples.vision.vit.runtime.python.imagenet --target s100 --variant tv-b16-imagenet1k-224-featuremap-int16-cpuptq-o1-20261105 --asset-id s:vit:s100/vit_tv_b16_imagenet1k_224_featuremap_int16_cpuptq_o1_20261105_nashe.hbm --model-path /path/to/vit_tv_b16_imagenet1k_224_featuremap_int16_cpuptq_o1_20261105_nashe.hbm --test-img /path/to/image.jpg
```

The explicit preparer reads the shared manifest and verifies SHA256 without silently replacing existing files. The runtime checks the selected board, artifact hash, actual model name and every tensor's name, shape and dtype. Source ONNX is a separately named host backend and never reported as HBM execution.

## Reproduce conversion

On x86 Linux/dev-server, use the exact trained checkpoint and source version in the registry. Source export uses Python3.10, Torch2.8.0, torchvision0.23.0 for the public torchvision models, and ORT1.19.2. The author exports load their trained weights strictly. Prepare the pinned real training partition locally; calibration data and raw tensors are private Workbench inputs and are not included in the release.

```bash
python3 -m utils.tools.torchvision_conversion --task vit --checkpoint /path/to/trained.pth --images /path/to/frozen-coco-train200 --output /path/to/new/export --native-commit e3374646ac035a85fce07b21379c1b06e2f9b66d
# In the exact cached CPU S SDK image recorded by digest in the registry:
hb_config_generator -f -m /path/to/new/export/model.onnx --march nash-e
# Copy the tracked recipe, set onnx_model/working_dir/cal_data_dir to these new paths.
cp samples/vision/vit/conversion/recipes/vit-public-s100-20261105.yaml /path/to/new/config.yaml
hb_compile -c /path/to/new/config.yaml
```

The source export compares all outputs on three actual inputs and deterministic random input. It retains the original numeric gate, with no dropped heads or random weights. Workbench also verified the installed CPU SDK and byte-exact calibration-loader boundary. All 200 real normalized NPY inputs are consumed, with no compiler-inserted preprocessing. The run uses INT16 max0.9999, O1, one core and two compiler jobs; hb_compile3.5.3, HMCT2.6.5, HBDK4.7.5.

Conversion, source host gates, complete original OE HTML/JSON, NodeInfo and observed HBM ABI passed. OE cosines are PTQ diagnostics and static compiler estimates are not measured inference speed. Board smoke, dataset accuracy, Runtime1/2 and C++1/2 remain **not-run**. This specification currently registers S100 only.
