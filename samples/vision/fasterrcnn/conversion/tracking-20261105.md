# S100 Faster R-CNN Tracking deployment

The 2026-11-05 tracking bundle uses the accepted `mbv3-320-native-20261103-o1` detector pair. CPU ByteTrack associates actual person detections across ordered video frames. There is no separate neural tracker checkpoint.

Download [the complete S100 deployment](https://archive.d-robotics.cc/downloads/rdk_model_zoo_web/rdk_s100/fasterrcnn/fasterrcnn_tracking_mbv3_320_native_20261105_s100_bundle.tar.gz) on dev-server or the board and verify [SHA256SUMS](https://archive.d-robotics.cc/downloads/rdk_model_zoo_web/assets/rdk_s100/fasterrcnn/fasterrcnn_tracking_mbv3_320_native_20261105_s100_bundle.tar/v1/SHA256SUMS). Extract both HBM files together. From repository root:

```bash
python3 -m samples.vision.fasterrcnn.runtime.python.main \
  --target s100 --variant mbv3-320-native-20261103-o1 \
  --parta-path /path/to/frcnn_mbv3_320_parta_nashe_native_20261103_o1.hbm \
  --partb-path /path/to/frcnn_mbv3_320_partb_nashe_native_20261103_o1.hbm \
  --track --video /path/to/video.mp4 \
  --save-path /path/to/result.mp4 --records /path/to/tracks.tsv
```

The exact paired descriptor retains both artifact hashes. The source is torchvision0.21.0 commit `7af698794eded568735f9519593603c1ec889eba`, official trained MobileNetV3-Large-320-FPN COCO_V1 weights. Original full source/ONNX detector checks, independent component conversion receipts, both complete original OE reports and the BSD-3-Clause license remain in the bundle. The new `host-tracking.json` records 30 genuine ordered frames through both source ONNX stages, Native RPN/RoIAlign/person decoding and CPU ByteTrack, with all five detector heads retained and stable adjacent track IDs. It is separate from the original detector full-output numeric checks.

The bundle requires both the original connected detector proof and its exact ordered-frame tracking proof. Board smoke, MOT accuracy, Runtime1/2 and C++1/2 are **not-run**. Component compiler estimates do not measure complete tracking speed.
