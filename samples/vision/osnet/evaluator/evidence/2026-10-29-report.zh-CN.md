# OSNet 在 RDK X5 上的转换与 C++ 推理实测

在本次通过精度门槛的候选中，推荐 **后半段 INT8 混合精度**：C++ E2E 中位数 **8.61 ms**，平均 **8.77 ms**，P95 **9.64 ms**。同模型 Python E2E 中位数为 **12.07 ms**，C++ 约快 **1.40 倍**。实际接口使用 L2 归一化输出，完整 Market1501 上的 Rank-1、mAP 分别下降 **0.18、0.21 个百分点**。

测试对象为官方 OSNet x1.0 Market1501 权重，输入高 256、宽 128，batch 为 1。转换及 FP32 参考计算在 d-robotics-dev 的 RTX 5090 服务器完成，推理性能来自真实 RDK X5。服务器所在城市未作独立核验。

## E2E 的范围与性能

E2E 从已解码的 RGB 人体图像块开始，包含缩放、输入数据排列、同步推理、输出复制和 L2 归一化；不包含摄像头采集、JPEG 解码、人体检测、跟踪或特征匹配。性能样本为 Market1501 的 64×128 RGB 图像块，缩放到 128×256。C++ 对该 2 倍放大使用保持 Pillow 像素结果一致的 NEON 快速路径，其他尺寸使用通用双线性实现，不能直接套用这一延迟。

| 方案 | Python 平均 ms | Python P50 ms | C++ 平均 ms | C++ P50 ms | C++ P95 ms |
|---|---:|---:|---:|---:|---:|
| INT8 | 5.056 | 5.045 | 2.144 | 1.670 | 3.488 |
| 大范围 INT16 混合精度 | 12.288 | 12.416 | 9.169 | 9.018 | 10.040 |
| 前半段 INT8 混合精度 | 6.637 | 6.678 | 3.671 | 3.363 | 4.753 |
| 后半段 INT8 混合精度 | 11.879 | 12.069 | 8.768 | 8.614 | 9.641 |

每个 C++ 候选预热 50 次、计时 3000 次；Python 计时 1000 次。单路同步调用，模型及输入输出缓冲区复用，模型加载和磁盘读取在计时外。BPU 频率为 996 MHz；保留板端原有 schedutil CPU 调频策略，没有强制锁频。不同方案顺序测试，P95 反映运行中的延迟波动。

C++ 的收益来自原生 Runtime 调用、复用内存和 NEON 缩放；更换编程语言没有改变 BIN 中的 BPU 网络。

## 完整测试集精度

数据为 Market1501，3368 张 query、15913 张 gallery，共 19281 张实际板端输出。排除 pid 为 −1 的无效样本，保留 pid 为 0 的干扰样本，检索时排除同身份同摄像头图像，无 reranking。校准只使用训练集的 128 张图片，随机种子为 20261029，与测试身份不重叠。

默认部署接口返回 L2 归一化后的 512 维特征，以下以归一化后的平方欧氏距离评测，排序等价于余弦距离。

| FP32 参考 | 94.2399 | 83.5696 | — | — |

为便于与原始 OSNet 评测比较，保留未归一化特征的平方欧氏距离结果：

| 方案 | Rank-1 % | mAP % | Rank-1 损失 pp | mAP 损失 pp |

精度门槛暂定为 Rank-1 和 mAP 均下降不超过 1 个绝对百分点，用户未指定数值。推荐方案在上述两种评测口径下均通过门槛，且在通过门槛的已测候选中 C++ E2E 平均延迟最低；该结论不代表穷尽所有配置后的全局最优。业务摄像头数据的精度仍应以对应的标注测试集衡量。

## 转换与一致性验证

使用官方同域预训练权重，严格加载 state_dict。将末端 Linear 与 BatchNorm1d 等价改写为 1×1 Conv 与 BatchNorm2d，适配 BPU 编译；16 张图的改写前后最大绝对误差为 6.08e−6。保留原始模型权重，没有额外训练。量化工具为 hb_mapper 1.24.3、HBDK 3.49.15；板端 libdnn 为 1.24.5、HBRT 为 3.15.55.0。

高精度配置采用 INT8 与 INT16 混合计算，部分池化等算子仍为 INT8。缩小精度范围的候选会将指定阶段恢复为 INT8，实际回退与层信息保存在转换配置和 quant-info.json 中。

所有上表 C++ 候选均在计时前对 32 张 query 图做输入逐字节检查，并与量化模拟器逐维比较特征，最大绝对误差均为 0。另对 12 种输入尺寸验证 C++ 与 Pillow 缩放及 hbm_runtime 输出一致，最大特征误差也为 0。相似度诊断仅用于排错，精度结论来自完整检索测试。

这些 RGB BIN 的元数据输入形状是 [1,256,128,3]，实际已验证的内存载荷是 RGB 减 128 后的有符号平面 CHW 字节。请使用随附的 C++ 或 hbm_runtime 示例。早期 pyeasy_dnn 数值检查未通过，其结果没有纳入推荐与性能表。

## 文件与复测

推荐模型：`models/spatial-rgb-late8.bin`，SHA256：`91a24b4a074576f41f24b97c0ad00c4ce7f2bc880fbfe92319dd9a2622549abc`。

`summary.json` 汇总所有候选；`results/` 保存完整精度、计时与一致性证据；`configs/` 保存转换 YAML；`scripts/osnet_e2e.cpp` 为原生实现；`scripts/infer_osnet_x5.py` 为 Python 接口；`cpp-fixture/` 保存可直接复测的固定输入及参考特征。`SHA256SUMS` 用于核对交付文件。

在已安装 X5 DNN SDK 的板端，进入交付目录后执行：

```bash
g++ -O3 -std=c++17 -Wall -Wextra scripts/osnet_e2e.cpp -ldnn -o osnet_e2e
./osnet_e2e models/spatial-rgb-late8.bin cpp-fixture/images.dat cpp-fixture/spatial-rgb-late8.f32 result.json 3000
python3 scripts/infer_osnet_x5.py models/spatial-rgb-late8.bin person_crop.jpg --output feature.npy
```

Python 默认返回 L2 归一化特征，追加 `--raw` 可取得未归一化特征。完整实验保存在服务器 `/data/zhengyi/osnet-x5-20261029` 和板端 `/root/osnet-x5-20261029`。原始校准数据路径写在 YAML 中，复用转换环境时应保持 `/work` 挂载或相应调整路径。
