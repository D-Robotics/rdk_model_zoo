# OSNet S-series Workbench acceptance

This workflow applies GUIDELINE.md v2.8 to OSNet x1.0 person re-identification. It uses Market1501 Rank-1/mAP, rather than the guide's YOLO COCO metrics. Each platform has a separate conversion run, board campaign, HBM and local candidate. S100 uses nash-e, S100P nash-m, and S600 nash-p. A target name alone does not establish runtime compatibility.

The source is the pinned x1.0 Market1501 checkpoint in model/artifacts.json. Export a spatial opset19 ONNX with `conversion/prepare.py export-s --help`; retain the export receipt. Final input is batch 1, F32 RGB NCHW [1,3,256,128], Pillow bilinear resize, division by 255 and ImageNet mean/std. Output is F32 [1,512,1,1]. Capture raw embeddings, then L2-normalize for squared Euclidean retrieval with no reranking.

Prepare 128 training crops using the frozen seed-20261029 manifest and `conversion/prepare_s.py data`. Evaluation uses all 3,368 queries and 15,913 valid gallery images; the same-camera/same-identity exclusion and junk handling are in metrics.py. Freeze the ordered image byte manifest before evaluation. The allowed absolute drop from FP32 is one percentage point for each metric.

Generate the full YAML with the installed `hb_config_generator -f -m MODEL.onnx --march MARCH`, then specialize it with `conversion/prepare_s.py config --template ... --target s100 --onnx ... --calibration ... --workdir ... --output ... --precision int16`. Invoke `hb_compile -c ...` in the pinned OE image. INT16 sets `quant_config.model_config.all_node_type=int16`; compiler fallbacks and actual node types remain in the original CSV. All other source, calibration and compiler choices remain fixed. The default INT8 experiment is retained separately if it misses the accuracy gate. Record actual calibration batch from the compile log; `jobs=8` does not prove calibration batch 8. Runtime input remains batch 1.

Run the sample directly on the matching board, using the manifest's exact variant and HBM:

```bash
python3 samples/vision/osnet/runtime/python/main.py \
  --target s100 --variant s100-f32-int16 --model-path /absolute/model.hbm \
  --test-img /absolute/person_crop.jpg --output feature.npy
python3 samples/vision/osnet/evaluator/main.py \
  --backend s100 --variant s100-f32-int16 --model-path /absolute/model.hbm \
  --dataset /absolute/Market1501 --output-dir /absolute/new-capture --capture-only
```

Replace both the target and variant for S100P/S600. On the host, use `--capture-dir /absolute/new-capture --dataset ... --output-dir /absolute/new-score` to score the saved full capture. The scoring receipt says board_test=not-run because that process only scores; capture.json independently records the board execution, model SHA and feature SHA.

Runtime performance uses the installed `hrt_model_exec perf` with a legal normalized F32 input, `--core_id 1`, concurrency 1 and 2, and three timed rounds of 200 total frames per condition. Read the installed help first. Runtime 3.13.6's boolean warmup only omits the first frame, so use a separate 20-frame device warmup and `--enable_warmup=false` for timed runs. Report this separate-process scope. Use profiler counts and wall time for aggregate throughput; do not derive concurrent FPS from latency.

C++ uses the UCP API and a dedicated model/buffer set per worker. Build with `-DOSNET_UCP -I/usr/hobot/include -L/usr/hobot/lib -ldnn -lhbucp`. The native executable accepts:

```bash
osnet --benchmark MODEL.hbm images.dat reference.f32 result.json 1 20 200 3
osnet --benchmark MODEL.hbm images.dat reference.f32 result.json 2 20 200 3
```

The private fixture contains 32 decoded crops and exact resize references; reference.f32 is independently generated by the Python SDK with the exact HBM. Each worker validates all 32 before timing. Every round warms each worker with 20 frames, then measures 200 per stream: 600/1,200 total timed frames. Preprocess includes resize and F32 normalization, runtime includes UCP/cache/output-copy work, and postprocess is L2 normalization. Same-frame stage sums and common wall throughput are saved. Decode, detection and retrieval are excluded. The launcher also supports TARGET, VARIANT, MODEL_PATH, FIXTURE_DIR, BENCHMARK, STREAMS, WARMUP, RUNS and ROUNDS.

Save board identity, OS/kernel, runtime/HBRT, CPU online count, governors/frequencies, BPU frequency and thermal readings before/during/after. Do not change clock policy. S100P's small root filesystem requires an existing data volume such as /mnt/ssd. Access is local Mac → Tailscale dev-s600 → S100/S100P, or directly to dev-s600 for S600.

Freeze the runtime source archive and controller hashes in the board campaign before execution. `evaluator/stage_s.py --workspace WB --build-id BUILD_ID` checks full accuracy, identities, native smoke outputs, six runtime rounds, two C++ conditions, raw frame statistics and environment evidence. It retains the original OE HTML, node CSV and compiler JSON and stages model/release.json/reports/SHA256SUMS under releases/models/osnet/osnet/reid/x1.0/TARGET. Technical acceptance does not set release approval; candidates stay unpublished.

Official references: [compile configuration](https://developer.d-robotics.cc/oe_s_doc/en/guide/ptq/ptq_tool/hb_compile/convert.html), [precision configuration](https://developer.d-robotics.cc/oe_s_doc/en/guide/ptq/ptq_tool/hb_compile/quant_config.html), [native performance tool](https://developer.d-robotics.cc/oe_s_doc/en/guide/ucp/runtime/tool_introduction/hrt_model_exec/performance_evaluation.html). Exact installed tool help and documentation bodies accompany the private Workbench run.

For the fixed-input ONNX stage check, this OE image's GPU PTQ inference raised a cuDNN execution/illegal-memory-access error. Use the installed `hmct.executor.ORTExecutor(model).to("cpu").create_session().forward({"images": input})` in a process separate from PyTorch; copy the returned embedding. CPU FP32/calibrated/PTQ checks and the official HBRuntime BC simulator succeeded with unchanged model/input bytes. PTQ calibration itself still ran on GPU at batch 8. Reuse an ONNX stage receipt across targets only when the exact model SHA and input SHA match; simulate each target's BC separately and compare it with that board's raw SDK output.

The frozen exporter reproduction is `osnet-s-20261030-export-r02`; its ONNX is byte-identical to the compilation input. The frozen full FP32 baseline is `osnet-s-float-20261030-r02`; its features are byte-identical to the earlier exploratory baseline.
