# Google SigLIP base224 complete FP32 export

This independent specification is `base-patch16-224-bicubic-dual-r02`.
It retains the learned attention pooling head and all 196×768 patch features
in a single ONNX graph. It does not export a text tower or substitute mean pooling.
The legacy packed artifacts and their historical measurements remain separate.

Source: [google/siglip-base-patch16-224](https://huggingface.co/google/siglip-base-patch16-224/tree/7fd15f0689c79d79e38b1c2e2e2370a7bf2761ed),
revision `7fd15f0689c79d79e38b1c2e2e2370a7bf2761ed`, Apache-2.0.
`model.safetensors` SHA256:
`2c63cb7d1f2e95ba501893cbb8faeb4ea9a3af295498d35097126228659c2af8`.
The strictly loaded vision subset comes from this complete trained checkpoint.

Run on the conversion server with the frozen Torch 2.8.0 / Transformers 4.51.3 /
ONNX 1.17.0 / ORT 1.19.2 CPU environment. Model files stay on that server.

```bash
python -m samples.vision.siglip.conversion.prepare_public \
  --source-dir /server/source/siglip-base224 \
  --source-manifest /server/frozen-coco-train200/calibration-manifest.json \
  --output /server/new-run/calibration
python -m samples.vision.siglip.conversion.export_public \
  --source-dir /server/source/siglip-base224 \
  --calibration-manifest /server/new-run/calibration/calibration-manifest.json \
  --output /server/new-run/export
```

For the eight independent validation images, run `prepare_public` again with
`--purpose validation`, their frozen eight-image source manifest and a separate
output directory. Pass its generated manifest as `--validation-manifest` to
`export_public`; the exporter then checks those inputs as well.

Input uses the pinned upstream processor: PIL bicubic direct resize to 224×224,
RGB rescale and mean/std 0.5, F32 NCHW. Every one of 200 real tensors is compared
byte-exact with that processor. This geometry differs from legacy AREA letterboxing.

The owner approved this specification's FP32 comparison on 2026-11-05:
`atol=0.006, rtol=0.001`, both full raw heads, finite values and exact shapes/dtypes.
All 200 real inputs plus seed-42 are checked; old `atol=0.0001` failures remain recorded.
Independent COCO val inputs are checked separately. This is a numerical export
contract, not dataset accuracy. FP64 diagnostic results cannot certify this FP32 graph.

S100 compilation requires a freshly generated complete SDK template, real reader
verification, CPU-provider comparison, compilation, original OE and measured HBM ABI.
An export receipt alone is not a downloadable HBM or a board test. All new board
smoke, accuracy, Runtime 1/2 and C++ 1/2 fields remain `not-run` until measured.

## Accepted S100 conversion and Native runtime

The complete S100 `nash-e` conversion is registered in [converted targets](converted_targets_20261105.json). The original full SDK configuration, portable recipe, installed CPU reference check, all-real-input reader check, original OE and measured compiled ABI are identified there. This independent specification currently registers S100 only; S100P/S600 need separate conversion and acceptance.

From repository root on dev-server or the selected board:

```bash
python3 -m utils.py_utils.converted_featuremap --sample siglip --target s100 --variant base-patch16-224-bicubic-dual-r02 --asset-id s:siglip:s100/siglip_base224_bicubic_dual_fp16_cpu_o1_20261105_nashe_r04.hbm
python3 -m samples.vision.siglip.runtime.python.public --target s100 --variant base-patch16-224-bicubic-dual-r02 --asset-id s:siglip:s100/siglip_base224_bicubic_dual_fp16_cpu_o1_20261105_nashe_r04.hbm --model-path /path/to/siglip_base224_bicubic_dual_fp16_cpu_o1_20261105_nashe_r04.hbm --image /path/to/input.jpg --output /path/to/new/features.npz
```

The explicit preparer verifies the published artifact SHA256. Board execution validates hardware, artifact, exact model name and every input/output name, shape and dtype. `--dry-run` resolves metadata without a model or board SDK. `--backend source-onnx --source-onnx /server/exact/export/model.onnx` is a separately named CPU reference and checks the source graph SHA256; it never executes an HBM. Raw output arrays stay on the executing machine.

The runtime applies the pinned PIL bicubic direct resize and RGB normalization, and saves both the learned attention-pooler output `[1,768]` and all patch features `[1,196,768]`. Optional patch PCA is a false-color feature visualization, not class labels or semantic segmentation. This vision-only specification does not contain a text encoder or claim zero-shot classification accuracy.

The recipe is [recipes/siglip-public-s100-20261105.yaml](recipes/siglip-public-s100-20261105.yaml). Prepare calibration with the committed `prepare_public` command above; its output contains one subdirectory per exact input name. In the pinned cached SDK image, generate a complete fresh template with `hb_config_generator -f -m export/model.onnx --march nash-e`, then apply the tracked recipe and point `onnx_model`, `working_dir` and `cal_data_dir` at the new run. Run `hb_compile -c config.yaml`. The accepted attempt consumed all 200 real inputs with source-normalized F32 and no compiler-inserted preprocessing. The policy is FP16 internal computation, calibration max percentile1.0, O1, one core and two compiler jobs; actual mixed precisions and CPU paths are preserved in OE.

The owner-approved FP32 gate is `atol=0.006, rtol=0.001`, every raw output value with exact finite shapes/dtypes. It is limited to this pinned independent specification (Workbench guidev2.21 §11.14). Source and installed SDK CPU comparisons include every calibration input, eight separate real held-out inputs and the deterministic random input. Earlier strict-gate failures remain in Workbench and are not relabeled.

Conversion and host gates passed. Board smoke, dataset accuracy, Runtime1/2 and C++1/2 remain **not-run**. OE cosine values and compiler estimates are diagnostics, not measured board performance or dataset accuracy.
