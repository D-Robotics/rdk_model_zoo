# Public S100 specification (2026-11-05)

`tv-r3d18-k400-16x112-featuremap-int16-cpuptq-o1-20261105` is an independently identified S100 (`nash-e`) conversion. Official torchvision R3D-18/Kinetics-400 weights and all 400 logits. Real videos supply 16 distinct frames at up to15fps; official bilinear resize128x171, center112, RGB normalization. The 100-clip UCF101 mirror subset covers 8 available actions and is pilot cross-dataset PTQ, not a Kinetics-400 accuracy survey.

The [conversion registry](converted_targets_20261105.json) records the trained source/checkpoint pair, compiled artifact, actual complete ABI, original configuration, calibration manifest and receipts. The model license is preserved in this directory. Historical specifications below the sample's new public-specification link keep their original contracts and measurements.

## Prepare and execute

On dev-server or the selected board, from repository root:

```bash
python3 -m utils.py_utils.converted_featuremap --sample 3dresnet --target s100 --variant tv-r3d18-k400-16x112-featuremap-int16-cpuptq-o1-20261105 --asset-id s:3dresnet:s100/3dresnet_tv_r3d18_k400_16x112_featuremap_int16_cpuptq_o1_20261105_nashe.hbm
python3 -m samples.vision.3dresnet.runtime.python.public --target s100 --variant tv-r3d18-k400-16x112-featuremap-int16-cpuptq-o1-20261105 --asset-id s:3dresnet:s100/3dresnet_tv_r3d18_k400_16x112_featuremap_int16_cpuptq_o1_20261105_nashe.hbm --model-path /path/to/3dresnet_tv_r3d18_k400_16x112_featuremap_int16_cpuptq_o1_20261105_nashe.hbm --clip /path/to/normalized-video.npy
```

The explicit preparer reads the shared manifest and verifies SHA256 without silently replacing existing files. The runtime checks the selected board, artifact hash, actual model name and every tensor's name, shape and dtype. Source ONNX is a separately named host backend and never reported as HBM execution.

## Reproduce conversion

On x86 Linux/dev-server, use the exact trained checkpoint and source version in the registry. Source export uses Python3.10, Torch2.8.0, torchvision0.23.0 for the public torchvision models, and ORT1.19.2. The author exports load their trained weights strictly. Prepare the pinned real training partition locally; calibration data and raw tensors are private Workbench inputs and are not included in the release.

```bash
python3 -m samples.vision.3dresnet.conversion.export_public --checkpoint-record /path/to/weight-source.json --videos /path/to/frozen-videos/manifest.json --output /path/to/new/export --native-commit 8c5c37bea7c7355212fa1b39b1f09cbfcf68d691
# In the exact cached CPU S SDK image recorded by digest in the registry:
hb_config_generator -f -m /path/to/new/export/model.onnx --march nash-e
# Copy the tracked recipe, set onnx_model/working_dir/cal_data_dir to these new paths.
cp samples/vision/3dresnet/conversion/recipes/3dresnet-public-s100-20261105.yaml /path/to/new/config.yaml
hb_compile -c /path/to/new/config.yaml
```

The source export compares all outputs on three actual inputs and deterministic random input. It retains the original numeric gate, with no dropped heads or random weights. Workbench also verified the installed CPU SDK and byte-exact calibration-loader boundary. All 100 real normalized NPY inputs are consumed, with no compiler-inserted preprocessing. The run uses INT16 max0.9999, O1, one core and two compiler jobs; hb_compile3.5.3, HMCT2.6.5, HBDK4.7.5.

Conversion, source host gates, complete original OE HTML/JSON, NodeInfo and observed HBM ABI passed. OE cosines are PTQ diagnostics and static compiler estimates are not measured inference speed. Board smoke, dataset accuracy, Runtime1/2 and C++1/2 remain **not-run**. This specification currently registers S100 only.
