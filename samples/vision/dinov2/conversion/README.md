# Conversion — DINOv2 ViT-S/14

The conversion implementation in this directory is real source capability, but no conversion, download, or board validation was executed in this migration.

<a id="source-model"></a>
## Source Model

- Framework: PyTorch from the OE 3.7.0 environment (Torch 2.6); the exporter supports Torch >=2.4 through the legacy exporter with `dynamo=False`.
- Source repository: `https://github.com/facebookresearch/dinov2`, revision `7764ea0f912e53c92e82eb78a2a1631e92725fc8`.
- Checkpoint: `dinov2_vits14_pretrain.pth`, SHA-256 `b938bf1bc15cd2ec0feacfe3a1bb553fe8ea9ca46a7e1d8d00217f29aef60cd9`.
- The exporter verifies the full checkpoint digest before `torch.load`; an HTTPS checkpoint is streamed to a temporary file and removed after verification/loading.

<a id="toolchain-targets"></a>
## Toolchain & Targets

The source recipe targets OpenExplore 3.7.0, hmct 2.6.5 / hbdk 4.7.5, and the three Nash marches. The OE image supplies Torch 2.6; install only the pinned ONNX additions. Conversion runs on x86 Linux, not on a board.

| Target | march | OE version | Config |
| --- | --- | --- | --- |
| s100 | `nash-e` | 3.7.0 | generated by `conversion/mapper.py` |
| s100p | `nash-m` | 3.7.0 | generated by `conversion/mapper.py` |
| s600 | `nash-p` | 3.7.0 | generated by `conversion/mapper.py` |

The source OE entry point is the following x86 Linux container command. It was not launched in this migration:

```bash
# cwd: repository root; source tree is mounted at /workspace
sudo docker run -it --rm --network host --shm-size=15g \
  -v "$(pwd)":/workspace -w /workspace \
  registry.d-robotics.cc/deliver/ai_toolchain_ubuntu_22_s100_s600_gpu:v3.7.0 \
  /bin/bash
```

### Prepare the pinned source and checkpoint

Run inside the OE container from `samples/vision/dinov2/conversion`. These commands fetch upstream materials and were not run in this migration. `dinov2/` is a new upstream checkout. Preserve the OE Torch installation and install only the pinned ONNX additions:

```bash
# cwd: samples/vision/dinov2/conversion, inside OE 3.7.0
# 1. The OE 3.7 image provides Torch 2.6; preserve it. The exporter supports
# Torch >=2.4 and this setup was validated with these ONNX packages.
python3 -c "import torch; print(torch.__version__)"
python3 -m pip install --upgrade onnx==1.19.0 onnxruntime==1.23.2
python3 -c "import onnx, onnxruntime; print(onnx.__version__, onnxruntime.__version__)"

# 2. Fetch the pinned source and official Apache-2.0 checkpoint.
git clone https://github.com/facebookresearch/dinov2.git
cd dinov2
git checkout 7764ea0f912e53c92e82eb78a2a1631e92725fc8
cd ..
wget https://dl.fbaipublicfiles.com/dinov2/dinov2_vits14/dinov2_vits14_pretrain.pth
printf '%s  %s\n' \
  b938bf1bc15cd2ec0feacfe3a1bb553fe8ea9ca46a7e1d8d00217f29aef60cd9 \
  dinov2_vits14_pretrain.pth | sha256sum -c -

```

<a id="export"></a>
## Export (ONNX)

`onnx_export/export_dinov2.py` verifies the pinned source checkout and checkpoint, builds ViT-S/14, bakes positional embeddings at 224, rewrites attention to explicit MatMul + Softmax + MatMul, and exports two outputs (`cls_feat`, `patch_feat`) with input `input` `(1,3,224,224)` float32. It also runs ONNXRuntime parity after export. The source command is:

```bash
# cwd: samples/vision/dinov2/conversion; prerequisites: OE environment, local source clone, verified checkpoint
python3 onnx_export/export_dinov2.py \
  --weights ./dinov2_vits14_pretrain.pth \
  --weights-sha256 b938bf1bc15cd2ec0feacfe3a1bb553fe8ea9ca46a7e1d8d00217f29aef60cd9 \
  --repo ./dinov2 \
  --repo-revision 7764ea0f912e53c92e82eb78a2a1631e92725fc8 \
  --out ./dinov2_vits14_224.onnx
# expect: ONNX input input=(1,3,224,224) F32; outputs cls_feat=(1,384), patch_feat=(1,256,384), plus parity logs
```

<a id="calibration"></a>
## Calibration

`mapper.py::prepare_calibration` reads real JPG/JPEG/PNG/BMP files from `--cal-images`, converts BGR to RGB, bicubic-resizes the short side to 256, center-crops 224, scales by `/255`, applies ImageNet mean/std, and writes contiguous float32 NCHW `.npy` tensors plus `calibration_manifest.json` in the temporary workspace. The source recommends 50 diverse real photographs; random or synthetic images are unsuitable.

The fixed recipe is featuremap float32 input, all-node int16 with int16 model outputs, and hmct's default modelwise KL search (the mapper intentionally leaves `calibration_type` unset). The source measured int8 activations and max/percentile calibration as failing configurations; those measurements are historical source data, not a run here.

```bash
# cwd: samples/vision/dinov2/conversion; prerequisite: ./cal_images contains real photographs
# Calibration is generated by the complete mapper command below; no standalone download is required.
python3 mapper.py --cal-images ./cal_images --march nash-e --output-dir ./output
# expect: temporary calibration_data_norm/*.npy and calibration_manifest.json before hb_compile
```


### Fixed-source quantization matrix (historical, Nash-E)

All five source rows are preserved below, including failed alternatives. None was rerun here. `(sim)` denotes toolchain simulation; it does not replace the failed executed values in that row.

| Config | cls cosine | patch cosine | Verdict |
|---|---|---|---|
| int8 + softmax-int32, featuremap, max | 0.081 | 0.803 | FAIL |
| int8 + softmax-int32, featuremap, KL | 0.892 | 0.894 | FAIL |
| int16, featuremap, max + 0.9999 | 0.184 | 0.840 | FAIL |
| int16, nv12, KL | 0.999 (sim) | 0.999 (sim) | FAIL (executed 0.01 / 0.12) |
| int16, featuremap, KL (this recipe) | **0.9989** | **0.9983** | **PASS** |

The fixed source also measured the `_reg4` register-token variant: per-tensor quantized cosine was about 0.80 versus about 0.999 for the plain variant, so `_reg4` was not shipped.

<a id="compile"></a>
## Compile

`mapper.py` performs export, calibration preparation, YAML generation, `hb_compile`, and artifact collection in that order. It checks `hb_compile --help`, writes a target-specific generated config, uses `featuremap` input and all-int16 quantization, then copies the HBM into `--output-dir`.

```bash
# cwd: samples/vision/dinov2/conversion; run inside the OE 3.7.0 image
python3 mapper.py \
  --weights ./dinov2_vits14_pretrain.pth \
  --weights-sha256 b938bf1bc15cd2ec0feacfe3a1bb553fe8ea9ca46a7e1d8d00217f29aef60cd9 \
  --repo ./dinov2 \
  --repo-revision 7764ea0f912e53c92e82eb78a2a1631e92725fc8 \
  --cal-images ./cal_images \
  --march nash-e \
  --output-dir ./output \
  --jobs 16
# expect: output/dinov2_vits14_224_int16_nashe.hbm and, when emitted, hb_compile_nashe.log
```

Use `--march nash-m` or `nash-p` for S100P or S600. Other mapper defaults are `--weights ./dinov2_vits14_pretrain.pth`, `--repo ./dinov2`, `--cal-images ./cal_images`, `--output-dir .`, `--jobs 16`, and no `--save-cache`; `--save-cache` retains the temporary workspace. Do not install the upstream `requirements.txt`, because it would downgrade the OE Torch installation to 2.0.

<a id="validation"></a>
## Post-Conversion Validation

The exporter performs ONNXRuntime float parity and reports cosine/max-absolute error. `mapper.py` confirms that `hb_compile` emits the expected HBM path. Board validation would then run the runtime smoke path and compare both outputs against float ONNX on identical preprocessed tensors. Neither conversion nor board validation was run here: status `not-run`.

<a id="known-gaps"></a>
## Known Gaps

- This migration did not download the checkpoint or HBM, enter the OE container, run export/calibration/compile, or use a board.
- The source supplies a complete conversion pipeline with pinned prerequisites; reproducibility, resulting artifacts, and parity numbers still require execution in the specified OE environment.
- Manifest HBM hashes are `sha256: null (unknown)`; a downloader-observed digest cannot verify publisher origin.
