# LiteAvatar conversion

[中文](README_cn.md) · [Sample](../README.md) · [Python runtime](../runtime/python/README.md)

This directory holds the recipe that converts the upstream
[HumanAIGC/lite-avatar](https://github.com/HumanAIGC/lite-avatar) pipeline
(audio-driven talking avatar) into the four S100 HBM artifacts the sample
runtime consumes: ONNX export, two lossless graph transforms, calibration
generation (including the runtime-exact decoder set), four `hb_compile`
configs and the cosine/board validation scripts.

The four artifacts (march `nash-e`, INT16 activations):

| Stage | Model | Input(s) | Output(s) | Config |
| --- | --- | --- | --- | --- |
| audio encoder | `encoder_avatar.onnx` (paraformer encoder, 50 hidden states) | `feats` [1,400,560] | `hidden_states` [1,400,50,512] | `encoder_avatar_config.yaml` |
| audio2mouth | `model_1_folded.onnx` | `input_au` [1,30,50,512] | `output` [1,30,32] (+`feat`) | `audio2mouth_int16_config.yaml` |
| face encoder | `net_encode.onnx` | `image` [1,3,384,384] | `f0..f3` pyramid | `net_encode_int16_config.yaml` |
| face decoder | `net_decode_deconv_inorm.onnx` | `f0;f1;f2;f3;mouth_param` | `mouth_image` [1,3,384,384] | `net_decode_deconv_inorm_fullrange_config.yaml` |

The decoder is **not** a pure BPU model: 21 InstanceNorm-subgraph nodes run as
FP32 on the CPU (`run_on_cpu` in the config) while the convolutions stay INT16
on the BPU; see [decoder transforms](#export) for why.

## Directory structure

All Python scripts below run from the root of an upstream `lite-avatar`
checkout with this directory copied into it as `conversion/`:

```text
lite-avatar/                  # upstream checkout @5b7ec850
├── conversion/               # copy of this directory (scripts/, configs)
│   ├── *_config.yaml         # the four hb_compile configs
│   ├── scripts/              # export / transform / calib / validation scripts
│   └── calib_data/           # generated by the calib scripts
├── data/preload/             # sample_data.zip extracted (bg_video.mp4, ref_frames/, *.pt)
├── weights/                  # download_model.sh output (model_1.onnx, model.pb, am.mvn, ...)
└── funasr_local/             # vendored upstream frontend (used by export/calib scripts)
```

This directory's contents:

conversion/

<a id="toolchain-targets"></a>
## Toolchain and targets

Two environments are used and never mixed:

1. **Export/calibration host** — CPU Python with the verified package set
   (Torch 2.3.1+cpu / torchaudio 2.3.1+cpu — the stack the upstream
   TorchScript weights and `funasr_local` are pinned to — plus onnx,
   **onnxsim** (the constant-input folding and the verified simplification
   depend on it), onnxruntime (export verification and the cosine check),
   `typeguard==2.13.3` (required by `funasr_local`), soundfile, librosa,
   opencv-python, numpy 1.26.4, scipy). No board SDK is needed:

   ```bash
   python3 -m venv .venv-export && . .venv-export/bin/activate
   pip install torch==2.3.1+cpu torchaudio==2.3.1+cpu \
       --index-url https://download.pytorch.org/whl/cpu
   pip install onnx onnxsim onnxruntime typeguard==2.13.3 \
       soundfile librosa opencv-python numpy==1.26.4 scipy
   ```

2. **OE toolchain** — Docker image
   `registry.d-robotics.cc/deliver/ai_toolchain_ubuntu_22_s100_s600_cpu:v3.7.0`
   (hbdk 4.7.5 / hmct 2.6.5 / `hb_compile` 3.5.3, march `nash-e`) for the four
   `hb_compile` runs. Run them **serially** (one compilation at a time); the
   toolchain is licensed per concurrent instance. The decoder config sets
   `jobs: 8`, the other three `jobs: 32`.

The only compile target is S100 (`nash-e`); no X5/S100P/S600 build exists or
is claimed.

<a id="export"></a>
## ONNX export and decoder transforms

Run from the checkout root (all default paths below are root-relative):

```bash
# 1. paraformer encoder with all 50 block hidden states stacked
#    (feeds audio2mouth; needs weights/.../model.pb + funasr_local)
python conversion/scripts/probe_paraformer_encoder.py
#    -> conversion/encoder_avatar.onnx

# 2. fold audio2mouth's constant inputs (input_ph zeros, input_sp=2, w=1.0).
#    The default --dst writes ./model_1_folded.onnx at the checkout root;
#    the compile config and the facegen calib script expect it under
#    conversion/, so pass --dst explicitly:
python conversion/scripts/fold_audio2mouth.py \
    --src weights/model_1.onnx --dst conversion/model_1_folded.onnx

# 3. face generator: TorchScript net_encode.pt/net_decode.pt from
#    data/preload (sample_data.zip) -> ONNX
python conversion/scripts/export_facegen.py --data_dir data/preload --out conversion
#    -> conversion/net_encode.onnx, conversion/net_decode.onnx
```

`net_decode.onnx` then needs two lossless, order-fixed transforms before PTQ;
both scripts verify equivalence against the source graph:

```bash
# 4. Resize -> ConvTranspose (3 bilinear x2 upsamples). hb_compile would
#    otherwise fall back to CPU for Resize and cost ~157 ms/frame
#    (measured mean of the untransformed decoder).
python conversion/scripts/replace_resize_deconv.py
#    -> conversion/net_decode_deconv.onnx

# 5. decompose the 3 affine-free InstanceNorm nodes into named plain ops so
#    run_on_cpu can hold the variance path in FP32
python conversion/scripts/decompose_inorm.py --verify
#    -> conversion/net_decode_deconv_inorm.onnx (cosine 1.000, max|diff| ~1e-6)
```

Why step 5 exists (root cause recorded in the config header): `hb_compile`
decomposes InstanceNormalization *during* its optimize pass and quantizes the
resulting variance path INT16 on the BPU; a `run_on_cpu` flag on the composite
node does not survive that decomposition (verified by byte-identical
`node_info.csv`). Pre-decomposing into plain named ops lets the config's
`run_on_cpu` list keep all 21 norm nodes (mean/centered/sq/var/vareps/invstd/
apply per decoder block) in FP32 on the CPU — `Pow(x,-0.5)` replaces
`Reciprocal(Sqrt())` to avoid a HzRsqrt fuse without a CPU implementation.
The 13 convolutions plus gamma/beta denorm stay INT16 BPU.

<a id="calibration"></a>
## Calibration data

Run from the checkout root; the scripts load `funasr_local` and the
`weights/` paraformer package:

```bash
# 6. encoder calib: post-CMVN featuremaps [1,400,560] from 16 kHz wavs.
#    Default sources: funasr_local/.../test_wavs (shipped in the upstream
#    checkout) plus the paraformer example dir under weights/.
python conversion/scripts/gen_calib_encoder.py
#    -> conversion/calib_data/encoder_avatar

# 7. audio2mouth calib: real input_au windows [1,30,50,512]. Same default
#    wav source; --paraformer_example_wav <dir> adds more utterances.
python conversion/scripts/gen_calib_audio2mouth.py
#    -> conversion/calib_data/audio2mouth

# 8. facegen calib: net_encode images [1,3,384,384] plus the decoder's
#    5-input set (mouth params from the FP32 folded audio2mouth ONNX on the
#    same windows)
python conversion/scripts/gen_calib_facegen.py
#    -> conversion/calib_data/facegen_encode, conversion/calib_data/facegen_decode
```

**Step 9 — runtime-exact decoder calibration (part of the verified recipe).**
The shipped v3 decoder is compiled from a decoder calibration set regenerated
with runtime-exact parameters: real butter-smoothed mouth params and
`net_encode.hbm` reference features, cycling the animation over the reference
frames. `gen_real_calib.py` embeds the validated frontend/param-loop code and
runs **on the board**, where the three compiled HBMs and the upstream checkout
are available; copy the directory back over
`conversion/calib_data/facegen_decode` before the decoder compile. The v3
recipe includes this step; an FP32-only decoder calibration was not verified
to reproduce the shipped artifact.

```bash
python3 conversion/scripts/gen_real_calib.py \
    --hbm-dir /path/to/hbm --data /path/to/preload \
    --mvn /path/to/am.mvn --wav /path/to/asr_example.wav \
    --out conversion/calib_data/facegen_decode \
    --upstream /path/to/lite-avatar --n-ref 30
```

<a id="compile"></a>
## Compile

Inside the OE toolchain container, **from the `conversion/` directory** (each
config's `onnx_model`, `cal_data_dir` and `working_dir` are `./`-relative to
it), serially:

```bash
cd conversion
hb_compile -c encoder_avatar_config.yaml
hb_compile -c audio2mouth_int16_config.yaml
hb_compile -c net_encode_int16_config.yaml
hb_compile -c net_decode_deconv_inorm_fullrange_config.yaml
```

Each config writes `./<prefix>_output/<prefix>.hbm` plus
`<prefix>_ptq_model.onnx` (quantized ONNX used by the cosine check). The
decoder config keeps `max_percentile: 1.0`, `jobs: 8` and the 21-node
`run_on_cpu` list exactly as verified; do not reorder or drop nodes from that
list.

Multi-input gotchas recorded in the configs: semicolon-separated `input_name`
/`input_shape`/`cal_data_dir`/`cal_data_type` (one entry per input, no spaces),
`norm_type: no_preprocess` for featuremaps, and a `mouth_param` of shape
[1,32] is accepted as featuremap without reshaping to [1,32,1,1].

<a id="validation"></a>
## Validation

Cosine (quantized ONNX vs FP32 ONNX, onnxruntime CPU; gate 0.95 on the
primary output):

```bash
python conversion/scripts/cosine_eval_ptq.py \
    --fp32 conversion/net_encode.onnx \
    --ptq  conversion/net_encode_int16_output/net_encode_int16_ptq_model.onnx \
    --calib conversion/calib_data/facegen_encode --n 50 --gate 0.95
# add --multi for the decoder's 5-subdir calib layout
```

Board acceptance (real BPU vs FP32 ONNX) — run `board_infer.py` **on the
board**, then `board_compare.py` on the host:

```bash
# on the board (hbm_runtime + numpy)
python3 conversion/scripts/board_infer.py \
    --hbm /path/on/board/net_decode_deconv_inorm_fullrange.hbm \
    --calib /path/on/board/calib_data/facegen_decode --multi --n 30 \
    --out /path/on/board/board_out/net_decode
# on the host, after fetching board_out/
python conversion/scripts/board_compare.py \
    --fp32 conversion/net_decode_deconv_inorm.onnx \
    --board_out conversion/board_out/net_decode \
    --calib conversion/calib_data/facegen_decode --multi --n 30 --gate 0.95
```

Artifact-matched board measurements for the shipped decoder
(`net_decode_deconv_inorm_fullrange.hbm`, sha256
`27e46cf9d6514f587d54c16cfa813583d89e59c9d5b5d4138efdf51e4d20df3c`; S100,
UCP/DNN 3.13.6, OE 3.7.0, nash-e, 2026-10-12; 166 frames of
`asr_example.wav` against the FP32 ONNX on identical inputs):

| Check | Result |
| --- | --- |
| decoder output vs FP32 reference | mean PSNR 48.94 dB, mean MAE 0.0052 on the decoder's normalized float output scale (a conversion-level tensor metric — a different scale from the uint8-frame PSNR/MAE of [evaluator/evaluate_frames.py](../evaluator/evaluate_frames.py)), no non-finite pixels |
| decoder latency (incl. the 21 CPU norm nodes) | mean 24.69 ms/frame |

The other three artifacts are validated with the same cosine/board scripts
against their own calibration sets, and the sample's paired board
verification compares every stage of the shipped set against the original
pipeline (see the sample README).

<a id="known-gaps"></a>
## Known gaps

- The ModelScope `LiteAvatarGallery` weights (`model_1.onnx`, `model.pb`)
  carry no stated license; they are user-prepared conversion inputs.
- An FP32-only decoder calibration (step 8 without step 9) was **not**
  verified to reproduce the shipped v3 artifact; the runtime-exact decoder
  calibration is part of the recipe.
- The untransformed decoder graph compiles with `Resize` on the CPU at
  ~157 ms/frame (measured mean); the Resize→ConvTranspose transform exists
  precisely to avoid that path.
- Only the S100 (`nash-e`) target is compiled and validated; no X5/S100P/S600
  build exists, and the OE image is licensed per concurrent instance (run
  the four compiles serially).
