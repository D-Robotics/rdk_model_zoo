# Mandarin XLSR53 complete FP32 export

This independent specification is `xlsr53-zh3503-30k-mask-r02`.
It retains all `[1,93,3503]` raw CTC logits and a real dynamic padding mask.
It does not inherit the unknown source identity or measurements of `asr.hbm`.

Source: [jonatasgrosman/wav2vec2-large-xlsr-53-chinese-zh-cn](https://huggingface.co/jonatasgrosman/wav2vec2-large-xlsr-53-chinese-zh-cn/tree/99ccb2737be22b8bb50dcfcc39ad4d567fb90cfd),
revision `99ccb2737be22b8bb50dcfcc39ad4d567fb90cfd`, Apache-2.0.
`pytorch_model.bin` SHA256:
`de031fd4b29e0c0667e5346450fadfe1326c89936b888b59c4ede608db763ee4`.
The checkpoint is strictly loaded; positional weight normalization is frozen only
after preserving its exact effective trained weights.

Run on the conversion server with the frozen Torch 2.8.0 / Transformers 4.51.3 /
ONNX 1.17.0 / ORT 1.19.2 CPU environment. Model files stay on that server.

```bash
python -m samples.speech.asr.conversion.prepare_public \
  --source-dir /server/source/wav2vec2-xlsr53-zh \
  --source-manifest /server/frozen-minds14-zh50/manifest.json \
  --output /server/new-run/calibration
python -m samples.speech.asr.conversion.export_public \
  --source-dir /server/source/wav2vec2-xlsr53-zh \
  --calibration-manifest /server/new-run/calibration/calibration-manifest.json \
  --output /server/new-run/export
```

Prepare the eight independent WAV windows with `prepare_public --purpose validation`
and a separate output directory. Each frozen source-manifest record gives
`wav_path`, `wav_sha256`, `start_sample` and `valid_samples` in the resampled 16kHz
domain. Pass the generated manifest through `export_public --validation-manifest`.

The native source frontend takes 16kHz mono F32, normalizes valid samples with the
upstream `variance + 1e-7`, then pads to 30000 samples. The F32 zero/one sample mask
is converted to int64 inside the graph. Both inputs are compared byte-exact with
the pinned upstream feature extractor for all 50 real calibration utterances.
This is separate from the legacy sample's `1e-5` normalization and unmasked input.

The owner approved this specification's FP32 comparison on 2026-11-05:
`atol=0.002, rtol=0.001`, every raw logit, finite values and exact shapes/dtypes.
All 50 real inputs plus seed-0 are checked; old `atol=0.0001` failures remain recorded.
Independent real WAV windows and padding boundaries are checked separately.
Native CTC text agreement is additional evidence and does not replace raw-logit checks
or dataset CER. Every 30000-sample window is independent.

S100 compilation still requires a full SDK template, actual reader verification,
CPU-provider comparison, complete compilation, OE and observed HBM ABI. A source
export is not HBM execution. New board smoke, accuracy, Runtime 1/2 and C++ 1/2
remain `not-run`; legacy C++ measurements do not certify this new masked contract.

## Accepted S100 conversion and Native runtime

The complete S100 `nash-e` conversion is registered in [converted targets](converted_targets_20261105.json). The original full SDK configuration, portable recipe, installed CPU reference check, all-real-input reader check, original OE and measured compiled ABI are identified there. This independent specification currently registers S100 only; S100P/S600 need separate conversion and acceptance.

From repository root on dev-server or the selected board:

```bash
python3 -m utils.py_utils.converted_featuremap --sample asr --target s100 --variant xlsr53-zh3503-30k-mask-r02 --asset-id s:asr:s100/asr_xlsr53_zh3503_30k_mask_int16_cpuptq_o1_20261105_nashe.hbm
python3 -m samples.speech.asr.runtime.python.public --target s100 --variant xlsr53-zh3503-30k-mask-r02 --asset-id s:asr:s100/asr_xlsr53_zh3503_30k_mask_int16_cpuptq_o1_20261105_nashe.hbm --model-path /path/to/asr_xlsr53_zh3503_30k_mask_int16_cpuptq_o1_20261105_nashe.hbm --audio-file /path/to/input.wav --output-dir /path/to/new/transcript
```

The explicit preparer verifies the published artifact SHA256. Board execution validates hardware, artifact, exact model name and every input/output name, shape and dtype. `--dry-run` resolves metadata without a model or board SDK. `--backend source-onnx --source-onnx /server/exact/export/model.onnx` is a separately named CPU reference and checks the source graph SHA256; it never executes an HBM. Raw output arrays stay on the executing machine.

The runtime reads bounded audio blocks, mixes channels to mono and explicitly resamples each independent window to 16kHz using SciPy `resample_poly`. Each window is at most30000 samples. It uses the upstream valid-sample normalization and both real F32 waveform/mask inputs, retains all93×3503 raw logits, and greedily decodes only valid feature frames with the complete pinned vocabulary. A tail too short for one convolution receptive field is explicitly recorded and accounted for; it is not silently dropped. This path does not add overlapping context or a language model. It does not inherit the old sample’s normalization or legacy concatenate-only decoder.

The recipe is [recipes/asr-public-s100-20261105.yaml](recipes/asr-public-s100-20261105.yaml). Prepare calibration with the committed `prepare_public` command above; its output contains one subdirectory per exact input name. In the pinned cached SDK image, generate a complete fresh template with `hb_config_generator -f -m export/model.onnx --march nash-e`, then apply the tracked recipe and point `onnx_model`, `working_dir` and `cal_data_dir` at the new run. Run `hb_compile -c config.yaml`. The accepted attempt consumed all 50 real inputs with source-normalized F32 and no compiler-inserted preprocessing. The policy is INT16 activation calibration with max0.9999, O1, one core and two compiler jobs; actual mixed precisions and CPU paths are preserved in OE.

The owner-approved FP32 gate is `atol=0.002, rtol=0.001`, every raw output value with exact finite shapes/dtypes. It is limited to this pinned independent specification (Workbench guidev2.21 §11.14). Source and installed SDK CPU comparisons include every calibration input, eight separate real held-out inputs and the deterministic random input. Earlier strict-gate failures remain in Workbench and are not relabeled.

Conversion and host gates passed. Board smoke, dataset accuracy, Runtime1/2 and C++1/2 remain **not-run**. OE cosine values and compiler estimates are diagnostics, not measured board performance or dataset accuracy.
