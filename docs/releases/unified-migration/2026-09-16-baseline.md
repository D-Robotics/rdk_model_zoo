### 4.2 已读到的真实平台差异

统一入口的 X5 profile 为 .bin、bayes-e/bayese、单一 packed NV12、X5 C++ 可用、默认检测 NMS IoU 0.70；S100/S100P/S600 profile 为 .hbm、nash-e/nash-m/nash-p、split NV12、Python 入口，默认检测 NMS IoU 0.45。YOLO26 OBB 的角度偏移、NMS 和模型输出协议按平台有分支；不能把 yolo26 的 LTRB/OBB 处理写成一个无条件相同函数。

发布行的资产数量也不是相同的制品：X5 ultralytics_yolo 为 67 个 .bin，X5 ultralytics_yolo26 为 25 个 .bin；S 对应行分别为 186 和 75 个 .hbm，且 S 资产按 nash-e/nash-m/nash-p 目录分组。模型文件不入 Git，资产路径和 URL 仍以各自 Manifest 为准。

### 4.3 统一不等于验收完成

HEAD 的统一 Sample 提供主机可读入口和测试文件，但 P0 没有加载 hbm_runtime、执行模型、编译 C++ 或比对输出。README/代码中的 platform profile 只能证明静态分支和入口存在，不能覆盖 X5、S100、S100P、S600 各组合的板端行为。逐函数旧 X5/S 进入新函数的映射未在本轮填写。

后续实施应以迁移表逐行补充旧符号、新符号、输入输出协议、制品和验证证据；候选目标路径不是完成状态。对于同名但输入布局、量化、NMS、C++/Python 或评估链不同的 Sample，先保留局部实现，再凭实际结果决定是否归并。

## 8. 可复查命令和证据边界

以下命令均为本次使用的本地只读检查，工作目录为本文件所在仓库：

    git rev-parse HEAD
    git log --all --format='%H %ad %s' --date=iso-strict -n 20
    git submodule status --recursive
    git ls-tree -r --name-only HEAD -- platforms/x5/samples platforms/s/samples
    git ls-tree -r --name-only HEAD -- '*.ipynb'
    Get-FileHash platforms/x5/docs/release/models.yaml -Algorithm SHA256
    Get-FileHash platforms/x5/docs/release/benchmarks.yaml -Algorithm SHA256
    Get-FileHash platforms/s/docs/release/models.yaml -Algorithm SHA256
    Get-FileHash platforms/s/docs/release/benchmarks.yaml -Algorithm SHA256

YAML 数字来自逐行解析对应提交树中的 models.yaml/benchmarks.yaml；目录计数排除了 samples/vision/README.md 和 samples/robotics/README.md 这样的占位目录。目录存在、下载脚本存在和 Manifest 有资产分别是三种事实，不能合并为“已支持”。
