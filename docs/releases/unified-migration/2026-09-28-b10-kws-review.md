`380e1a2bf42041af54be6f34935e50197cfadff9`, audited in
[B10 source review](2026-09-28-b10-source-review.md). The original mono PCM16

Canonical `samples/speech/kws` selects only `s:kws:s100/kws.hbm`; no S600/S100P/X5
fallback. The active manifest download path now names `model/download.sh`.
Preparation explicitly downloads; runtime does not install/download. An external
model path requires the exact asset ID. The publication lacks an independent
checksum; reports retain observed bytes without claiming origin authentication.

The task class contains construction/preprocess/forward/postprocess/predict only.
Audio I/O, fixed frontend, binding, score conversion and reporting are separate.
The SDK runner delegates to existing SingleArrayRunner, including real target/
file gates, metadata checks, scheduling and independently owned raw arrays.
Forward returns raw output; postprocessing computes max of existing probabilities,
with shared SCALE conversion for integer outputs and no second sigmoid.

## Explicit source corrections and restrictions

- 60000 samples at 16 kHz is 3.75 seconds, not 60 seconds. Truncation/padding
  counts are reported. No implicit full-recording scan, resampling or channel mix.
- Actual PaddleAudio fbank is `[373,80]`; the source's own unsqueeze yields
  `[1,373,80]`, not the runtime README's `[1,1,T,80]` claim. The canonical binder
  requires the actual frontend contract. This is host feature evidence, not an
  observed HBM metadata capture; an incompatible SDK descriptor is refused.
- The sole publication accepts the four fixed source frontend defaults. Formerly
  unchecked overrides now fail explicitly rather than silently change feature
  semantics. A custom export needs a separate model/feature contract.
- The source did not verify output quantization/range. Integers now require
  valid metadata; all reduced probabilities must be finite in [0,1].
- A CLI threshold (default 0.5, score >= threshold) produces an explicit boolean;
  it does not modify the source max-score value or claim threshold calibration.
- Runtime report paths are new directories; stale outputs cannot stand in for
  a successful prediction. Audio paths are expanded consistently before decoding
  and digest capture.

## Real frontend evidence

[check_frontend.py](evidence/2026-09-28-b10-kws/check_frontend.py) executes real
PaddlePaddle 3.3.1 / PaddleAudio 1.0.2 in an isolated Python 3.13 environment.
[Results](evidence/2026-09-28-b10-kws/frontend-results.json) retain package versions,
source/audio/feature hashes, shape/dtype and comparisons for the original clip,
16000-sample silence and an 80000-sample repeated clip. The unchanged source
`audio_trunc` method is extracted and executed, followed by its actual fbank call.
All padded/truncated waveforms and all feature values match exactly (maxdiff 0).
SoundFile and actual `paddleaudio.load` PCM decoding also match on the source clip.
No HBM was loaded and no synthetic score is reported as a measured model score.

Initial environment discovery missed PaddleAudio's dynamically installed top-level
`load` and briefly suggested it was absent. Actual import/execution confirms it
exists; that progress statement is corrected here. SoundFile remains separate
because file I/O does not belong in the task, not because `load` is unavailable.
The isolated dependency run also exposed undeclared tqdm/scikit-learn/PyYAML
requirements; the full setup and freeze are now recorded.

## Customer documentation and evaluation

Twelve bilingual README files cover root/model/runtime/conversion/evaluator/test
input, including every CLI parameter, output interpretation, exact API example,
source performance and truthful conversion gaps. There is no original C++ KWS
implementation, so none is invented. Root and sample indexes now list 45 vision
samples (restoring the missing YOLOE navigation) plus KWS speech.

Conversion source had only a placeholder and no checkpoint/export/calibration/
compiler recipe. The guide records these prerequisites and a validation path;
no made-up conversion command or acceptance claim replaces them. Historical
S100 1.176 ms / 830.875 FPS and ~0.985 score remain explicitly source-only.

The new offline evaluator calculates threshold confusion, accuracy, precision,
recall, F1 and per-window false accept/reject rates from a labeled prediction
file. Empty denominators become null; invalid/duplicate/nonfinite rows fail.
Prediction bytes are hashed, supplied provenance is preserved as unverified,
and the report states that scoring did not execute inference. The documentation
example is labeled synthetic. It does not claim dataset or per-hour wake accuracy.
