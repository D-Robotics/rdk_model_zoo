## Findings and fix status

Three actionable findings were reported and all three are fixed. No remaining
P1/P2 finding was reproduced in this scoped review. Locations below refer to
the reviewed working tree, not original-source lines.

### 1. P2 — Preserve automatic platform resolution in the default constructor — fixed

The first implementation passed `platform=None` through to model binding.
`YOLO26Detect(YOLO26DetectConfig("fixture.bin", classes_num=1),
runtime_loader=...)` therefore failed with
`A concrete target profile is required to bind NV12 inputs`, despite complete
X5 model metadata. The old `Yolo26Runtime.__init__` resolved the platform and
stored it on the configuration before loading the model.

The fix in `yolo26_det.py:137-143` resolves the default platform once before
constructing the real runner and persists it in the configuration. The
reviewer mocked board identification to X5, supplied complete runtime
metadata, and verified successful binding, stored target `x5`, and exactly
one resolver call. Injected callable runners retain the host-only seam.

### 2. P2 — Reject quantized metadata for the finite LTRB protocol — fixed

The first implementation reused DFL's generic quantization allowance. An
LTRB selection with all six physical outputs declared `int8` and explicit
`scale=0.5, zero_point=0` bound successfully and returned float32 semantic
outputs. That contradicted Task 1 and the reviewed NHWC floating LTRB
protocol; no quantized YOLO26 artifact was audited.

The protocol guard in `model_binding.py:465-468` now rejects quantization
metadata for LTRB before the shared quantization adapter can accept it.
The reviewer independently verified rejection of both int8-with-scale and
float32-with-scale metadata. The existing integer-without-scale rejection
also passes. DFL's explicit quantization contract remains separate.

### 3. P2 — Keep class selection and confidence filtering in raw-logit space — fixed

The first shared decoder took class argmax after sigmoid. For float32 logits
`[18, 20]`, both sigmoid values round to `1.0`; the new path selected class 0,
while the original `filter_classification` selected class 1. Both the
original DFL detector and the original YOLO26 detector used raw argmax.
The defect already existed in the P1 decoder, but moving YOLO26 onto it
introduced a YOLO26 regression relative to the fixed original commit.

The first fix restored raw argmax, and dedicated LTRB and DFL fixtures both
returned class 1. That fix still used sigmoid-space `scores >= score_thres`
for confidence filtering. The reviewer reproduced a remaining change from
original behavior even with the default `0.25` setting:

```python
threshold = 0.25
raw_threshold = -np.log(1.0 / threshold - 1.0)
logit = np.nextafter(np.float32(raw_threshold), np.float32(-np.inf))
# float(logit) == -1.0986124277114868
```

With all other logits set to `-20`, original `filter_classification` rejected
this cell, while that intermediate `decode_ltrb` returned one detection with
score `0.25`. This was executed with NumPy 2.2.6, using the unchanged original
helper as the reference.

The final fix at `decode.py:238-251` keeps raw argmax and uses the original
raw-logit threshold in the logits branch. The explicit DFL probabilities mode
keeps its probability threshold. The reviewer compared both LTRB and DFL
against original `filter_classification` for 90 boundary cases: 15 thresholds,
each with the adjacent lower float32, rounded float32, and adjacent higher
float32 raw threshold. Candidate counts match the original in every case,
including the default-threshold reproduction above. The checked-in test also
covers explicit probability-domain filtering. This closes the same
source-semantics finding; it does not characterize the earlier DFL defect as
newly introduced by P2.

## Standards and boundary review

- `LTRBDetectionContract` explicitly declares three class heads and three
  direct four-channel LTRB heads. It does not send four offsets through DFL
  softmax. The deterministic direct-offset test produces
  `[-4, -12, 28, 36]` in model coordinates, which differs from a DFL
  interpretation of the same numbers.
- Input transport remains in the reviewed NV12 binding. Physical output
  names are bound from complete shape/dtype metadata to semantic roles.
  The reviewer loaded the five saved YOLO26 metadata records and bound all
  successfully on the host: X5 uses `output0/580`, S uses `output0/609` for
  the first class/box pair. This is inspection of recorded metadata, not
  five new board executions.
- SDK loading and model execution stay in `ModelRunner`; image preparation,
  coordinate restoration and task results stay in the task helpers.
  An injected callable is executed once and returns tuple-compatible
  `DetectionResult`. Actual physical outputs are validated after execution;
  semantic outputs supplied by an injected runner are validated by decoding.
- Twelve additional negative host cases reject NCHW/flat metadata, NCHW/flat
  semantic tensors, NaN/Inf (including an otherwise filtered-out cell),
  incorrect actual shape, actual dtype differing from metadata, and raw
  integer semantic tensors. These supplement the tests checked into the
  sample; they do not establish support for another layout/protocol.
- `test_yolo26.py` now supplies required NV12/U8 input and F32 output metadata.
  Its detect fixture injects `runtime_loader` and still executes
  `RuntimeMetadata.from_runtime` and `bind_model`. The other task fixtures
  retain their earlier runtime-loading seam. No production validation was
  relaxed to make this fixture pass.

## Source behavior and shared DFL comparison

The original `YOLO26Detect.post_process` class was extracted from the fixed
commit and executed as the reference, using synthetic tensors and the
unchanged postprocess helpers. Twelve cases covered X5/S100 ordering,
square stretch and letterbox, non-square stretch, and two deterministic
seeds. Class IDs and order matched exactly. The largest absolute box
difference was `7.62939453125e-06`; the largest score difference was
`2.9802322387695312e-08`. The assertions used box `atol=2e-5, rtol=1e-6`
and score `atol=1e-7, rtol=1e-6`.

The shared DFL decoder was compared with the verified P1 archive over 36
deterministic cases: input sizes `(64,64)`, `(64,96)`, `(128,64)`; logits or
probabilities; no/classwise/agnostic NMS; two seeds. Boxes, scores, and IDs
matched element-for-element after both classification fixes. The 90 separate
boundary cases use the original helper as reference because the P1 archive
contains the earlier classification defect.

Actual-resize geometry is an intentional behavior change inherited from P1:
the inverse uses integer resized dimensions and the recorded X/Y scales.
For a rounded non-square letterbox it need not equal the old ideal-scale
inverse. The contract explicitly documents that difference. The normal
YOLO26 source comparison above excludes rounded non-square letterbox;
the existing DFL test verifies the actual-resize inverse separately.
