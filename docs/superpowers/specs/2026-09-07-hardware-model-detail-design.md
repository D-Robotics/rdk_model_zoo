# RDK Model Zoo：硬件导航与模型详情页设计

日期：2026-09-07

状态：访谈需求已逐项确认；完整页面方案待用户审阅。

本设计替代 `2026-09-07-multiplatform-variant-catalog-design.md` 中的卡片身份、平台展示和详情布局。当前任务是重新设计目录与详情，不进行板卡测试，不重打已有 Release Tag。

## 1. 已确认的产品约定

- 家族级卡片：YOLOv8 的 N/S/M/L/X 合并，YOLOv9 独立；MobileNet V1–V4 合并。
- 目录平台筛选固定为：全部、X3、X5、S100、S100P、S600。界面不显示笼统的 S 或原始硬件长名称。
- 点击卡片进入独立详情页；不用弹窗。
- 详情使用硬件 Tab；尚未适配的硬件直接隐藏。
- 详情每行对应当前硬件下的模型规格和输入尺寸，横向展示各线程数的延迟与 FPS。
- 同一行同时展示浮点精度、量化精度和精度保持率，保持率使用百分数，例如 94% 或原表的 95.42%。
- 同一行下载当前硬件可直接运行的量化模型文件；不提供 ONNX 下载入口。
- 已适配且有量化文件、但缺少 Benchmark 的规格仍然展示，并可下载；相应指标标注“尚未实测”。
- YOLOE 不进入目录。

## 2. 目录页

页面保持搜索和家族卡片浏览。平台选择器显示固定顺序：全部 / X3 / X5 / S100 / S100P / S600。选择某个平台只显示已适配该平台的家族。没有匹配模型时显示空结果，不删掉平台筛选项。

卡片显示家族名、任务类型、当前收录的规格、已适配硬件标签和“查看模型”。不把某一硬件或某个规格的最佳性能当作整个家族的性能，也不显示一个笼统的“精度尚未实测”覆盖其他规格的已测结果。

点击卡片的硬件标签可直接进入该家族对应硬件的详情。点击卡片主体时优先继承目录当前平台；无平台选择时使用详情固定硬件顺序中的第一个已适配项。返回目录恢复搜索和筛选状态。

## 3. 独立详情页

页面从上至下：

1. 返回目录、家族名和简短任务说明。
2. 硬件 Tab，按 X3 / X5 / S100 / S100P / S600 顺序，仅显示已适配项。
3. 当前硬件支持的任务选项，例如检测、分割、姿态、分类。只有一个任务时省略切换控件。
4. 当前任务的规格表。N/S/M/L/X 全部直接以行展示，不再增加尺寸选择步骤。
5. 按行展开的测试条件、其他指标、文件详情和原始 Benchmark 来源。

切换硬件同时切换规格、测试指标、适用说明、样例文档与下载地址；不把上一硬件的指标或文件留在页面上。切换时尽可能保留任务，若目标硬件没有该任务，则选择该硬件实际支持的首个任务。

保留现有静态 Pages 部署，建议以 URL 查询参数表达独立页面状态：`?model=yolov8&hardware=x5&task=detect`。这是独立内容视图，具有页面标题、前进后退和刷新直达能力；不依赖服务器路径重写。兼容已有 `?model=...` 链接。

## 4. 规格表

桌面端使用分组表头：

| 规格 | 输入尺寸 | 1 线程：延迟 / FPS | 2 线程：延迟 / FPS | 浮点精度 | 量化精度 | 保持率 | 下载 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| YOLOv8n | 640×640 | 两个横向数值单元格 | 两个横向数值单元格 | 原表数值 | 原表数值 | 原表百分数 | 对应量化文件 |

每个“延迟 / FPS”组内是两个横向列，不把指标拆成上下两行。单位放在表头：延迟 ms、吞吐 FPS。输入格式等必要信息可放在输入尺寸下方的辅助文字。

任务不同则切换或分组展示，不混合检测 mAP、分割 mask mAP 和分类 Top-1。精度区域必须标明指标和数据集；同一表的精度口径不一致时分组展示。精度仍按同一条规格行对应。原始数值使用同一种明确的单位；例如 0.306 ratio 显示为 30.6%，不显示无解释的 ratio。

MobileNet 在规格列显示版本与变体，例如 V1、V2、V3 Small、V4 某规格；有不同输入尺寸或运行产物的分别成行。“尺寸”同时照顾变体大小与输入分辨率，不臆造参数量或文件大小。

已记录的 4/8 等线程配置也横向扩展为同类列组；不丢弃原始 Benchmark 的额外线程数据。未记录线程数的指标明确归入“线程数未记录”，不默认当作 1 线程。BPU 推理、端到端和 CPU 后处理分别标明，不拼成同一测试条件。

窄屏允许表格局部横向滚动，规格列保持可定位；页面主体不横向溢出。硬件 Tab 和任务控件可换行，保持文字可读。下载入口留在对应规格行。

## 5. 精度保持率

优先显示原始 Benchmark 显式记录的 retention 指标和原有有效小数。例如当前 X5 YOLOv8n 检测记录：浮点 0.306、量化 0.292、保持率 95.42%。原表只有 94% 时即显示 94%，不强制补成 94.00%。

没有显式保持率时，仅对同一模型产物、相同数据集、相同指标、可比评测条件的浮点与量化结果计算：量化精度 / 浮点精度 × 100%，最多保留两位小数。在行详情中标明“由原始精度计算”。不能混用 mAP50 与 mAP50–95、不同数据集或不同硬件量化产物。

缺少任一实测精度则对应列和保持率显示“尚未实测”；有数据但口径不能比较则保持率显示“不可比较”。浮点分母为 0 时不计算。保持率不截断在 100%，不改名为精度损失。

MAE/RMSE 等越低越好的误差指标不套用上述准确率公式；除非原始 Benchmark 显式定义保持率，否则保持率显示“不适用”。只存在余弦相似度等验证指标的模型保留其指标名称与数值，不伪装成浮点/量化准确率对比。

## 6. 硬件支持与产物对应

硬件身份必须与源仓库分支身份分开。内部 release line 可以是 x3/x5/s；用户硬件为 X3/X5/S100/S100P/S600。S 的分支身份不能自动推导出三个 S 系列硬件都已适配。

已适配关系来自明确的运行产物兼容性、Manifest 或样例文档说明；不能只靠存在性能数据来判断。没有实测 Benchmark 但存在已明确适配的量化文件时仍有硬件 Tab 和规格行。未经证实的兼容性不对外展示成支持。

每个可展示规格至少有稳定的家族、任务、规格、输入配置、硬件和产物身份。指标按兼容的产物和测试条件关联，下载按精确产物关联，均保留来源。

优先使用现有 `asset_filename` 关联。缺少该字段时在目录构建层添加受校验的显式映射，并以真实文件、输入、任务、硬件说明核对。不能通过第一个同名/同前缀文件碰运气匹配。多个不同构建产物不要合并成一个假想的测试结果。

下载列仅出现当前硬件的量化/编译产物，例如 `.bin`、`.hbm`；模型格式和具体后缀以现有文件为准。单文件直接链接原始下载地址；多文件组合在该行展开列出必要文件。不伪造打包下载链接，不把普通文档链接标为模型下载。尚未记录直接地址时说明“下载地址未记录”，必要时提供已有真实下载说明。

同一示例目录内的其他模型家族文件不得混入当前家族的下载。硬件适用范围、源文件路径和 release/ref 应在构建时保留，不能只按文件 basename 去重。

## 7. 当前实现中需消除的偏差

检查基线：`f1c5769`。

- `filters.ts` 直接从 benchmark.hardware 生成平台选项，因此会显示硬件长名称且遗漏未测但已适配的硬件。
- `model-details.ts` 仍是弹窗和按仓库分支上下堆叠的多张表，下载列表与规格行分离。
- `multiplatform-catalog.ts` 拆分家族时继承整个样例 assets，导致下载不能精确对应家族和规格。
- `metricCell` 把未注明 concurrency 的指标当作 1 线程，并按 metric 名找首个数值，可能混淆测量范围。
- 例如当前 X3 YOLOv8n 的 34.1 FPS 为 BPU throughput summary，线程数未记录；6 ms 明确为 Python 后处理，不能放进“1 线程推理延迟”单元格。
- 当前 accuracyCell 只取第一个 stage，未展示对应指标名、保持率和其他有效精度指标。

这些属于实现本设计所需的数据和显示修正，不要求补做任何板卡测量。

## 8. 实现边界与验收

目录构建层负责家族/规格/硬件/产物映射和来源校验；查询层负责固定硬件筛选；页面状态层负责 URL 与历史导航；详情层负责硬件/任务切换与规格表；数值格式层负责指标单位和保持率。沿用现有静态 TypeScript 工程和中英双语、主题、键盘操作能力。

验收覆盖：

1. 目录准确显示固定的五种硬件；详情仅显示已适配硬件。
2. YOLOv8 尺寸合并在家族内，YOLOv9 独立，MobileNet 版本合并；排除 YOLOE。
3. 从目录进入、刷新详情、复制链接、浏览器前进后退、返回目录均保留合理状态。
4. 硬件/任务切换后没有来自其他硬件/任务的指标或文件。
5. 同行展示模型规格、输入、线程延迟/FPS、浮点精度、量化精度、保持率和正确量化文件。
6. 已适配但未测的规格可下载；未适配项隐藏；数据缺失不写“未公开”。
7. 保持率显式值优先、可比性、零分母、超过 100%、误差指标不适用等边界正确。
8. X3 后处理不冒充 BPU 推理延迟；线程条件不明不冒充 1 线程；其他线程数据仍可访问。
9. 在常见桌面和手机宽度检查实际页面布局，保留键盘焦点、语义表头和硬件切换可访问性。
10. 发布前运行相关数据关联、路由和 UI 验证及现有构建检查；发布后检查公网入口与详情深链。

完整方案审阅通过后再编写实施计划和修改生产代码。
