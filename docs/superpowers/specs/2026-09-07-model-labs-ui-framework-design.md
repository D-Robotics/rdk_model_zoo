# RDK Model Zoo UI 与框架设计需求书

日期：2026-09-07

版本：设计稿 v1.0，供 UI／框架实现与 Benchmark 数据刷新协作使用

实现基线：官方仓库 `D-Robotics/rdk_model_zoo`，已上线提交 `152bae0`

本轮交付：设计需求文档；本文件中的新增页面、组件和数据契约尚未实施。

## 1. 产品目标与工作边界

将现有模型目录升级成便于浏览、筛选、选型和下载的模型门户。用户应能依次回答：

1. 有哪些模型家族适合我的任务？
2. 我的 X3／X5／S100／S100P／S600 支持哪些规格？
3. 同一规格的线程延迟、吞吐、量化前后精度是什么？
4. 应下载哪个可直接运行的模型文件，测试数据来自哪里？

本轮重点是 UI 信息架构、视觉布局、交互、组件拆分及数据层与 UI 的契约。另一位数据 Agent 负责逐一阅读原始 Benchmark 表格、核对数值、完善规格与文件关联。两者必须通过约定的数据接口衔接，避免在页面组件中补写模型数据。

不开展板卡测试；不移动已有 Release Tag；不新增登录、在线推理、聊天助手、上传模型、模型交易或后端管理系统。既有发布机制继续沿用。

### 1.1 必须延续的产品规则

| 主题 | 约束 |
| --- | --- |
| 模型家族 | YOLOv8 的 N/S/M/L/X 在同一卡片和详情页；YOLOv9 独立；MobileNet V1–V4 合并。骨干网络名不能把 UNet-MobileNet 等任务模型误并入分类家族。 |
| 硬件名称 | 用户界面统一为 X3、X5、S100、S100P、S600；分支名 `s` 不是硬件。 |
| 详情页 | 独立页面，支持深链、刷新、前进后退和返回筛选结果；不改回弹窗。 |
| 支持关系 | 未适配硬件直接隐藏；有适配产物但未测 Benchmark 的硬件仍展示。 |
| 表格 | 同一规格的延迟和 FPS 横向成组，浮点精度、量化精度、保持率和下载在同一逻辑行。 |
| 精度 | 显示明确指标及数据集；保持率采用原表百分数，如 94% 或 95.42%，不改名为精度损失。 |
| 下载 | 只展示当前硬件可运行的量化／编译产物，当前以 `.bin`、`.hbm` 为主；不提供 ONNX 下载入口。必要的运行配套文件须有明确组合关系。 |
| 缺失信息 | 实测缺失写“尚未实测”；元数据缺失写“未记录”；不得用“未公开／保密”解释缺失。 |
| 排除项 | YOLOE 不进入目录、搜索、统计或下载。 |

## 2. 参考站分析与设计取舍

实际浏览了 [Horizon ModelLabs 目录](https://oe.horizon.auto/labs) 和 [Resnet50 详情页](https://oe.horizon.auto/labs/Resnet50)，查看了页面截图、目录筛选控件与详情信息结构。以下观察仅对应本次访问可见页面，不代表其全部功能。

| 参考站可见设计 | RDK Model Zoo 的采用方式 |
| --- | --- |
| 顶部统一导航、概述区与简短统计 | 建立统一页面外壳；概述区压缩，避免首屏只看到介绍。 |
| 左侧场景分层筛选，右侧模型网格 | 采用桌面侧栏＋模型卡片网格；硬件另设显式快捷栏，五款平台直接可见。 |
| 图文模型卡片：效果图、名称、描述、任务与芯片标签 | 采用真实样例缩略图和明确的卡片层级，模型家族作为卡片身份。 |
| 独立详情页：介绍、图示、部署指标、下载分区 | 借鉴分区和阅读顺序，但将规格 Benchmark 表提前，缩小介绍和图片。 |
| 详情按芯片展示 FPS、Latency、Memory 指标卡 | 不把这种指标卡作为 RDK 的主数据视图；我们的多规格、多线程、精度对照仍用表格。 |
| 深色蓝调、较大的图文封面区 | 借鉴留白和层次，不复制品牌图形、蓝色主按钮或整页大封面；保留 RDK 橙色识别。 |

### 2.1 方案选择

| 方案 | 收益与代价 | 结论 |
| --- | --- | --- |
| 在现有 TypeScript/Vite 上重组布局与组件 | 沿用数据与部署能力，集中解决 UI 和边界问题；需拆开当前较大的详情渲染模块。 | **本轮采用** |
| 迁移 React/Vue 并接入完整组件库 | 未来交互扩展方便，但产生迁移、样式、路由及测试成本；当前需求不依赖它。 | 本轮不迁移 |
| 只替换皮肤与卡片图片 | 改动小，但无法解决数据契约、表格结构、筛选层级和维护问题。 | 不足以满足目标 |

这里的“框架优化”指页面外壳、组件边界、页面状态、数据适配及发布产物的组织，不预设更换前端技术栈。

## 3. 页面信息架构

站点保留两个主要页面：模型目录、模型家族详情。帮助说明以现有仓库文档链接和表格内说明承载，不为本轮增加一套内容站点。

│   分类／检测／分割…  │                                        │
│ 语音与音频          │ [效果图]       [效果图]       [效果图]    │
│ 多模态              │ YOLOv8        MobileNet       …          │

│ 更多筛选（折叠）    │ 查看模型 →     查看模型 →                  │

#### CAT-01：概述与导航

- 顶栏控制在 56–64 px；语言和主题融入顶栏，避免单独占据一整行。
- 标题、简述与统计属于同一紧凑概述区，桌面高度目标不超过 140 px。
- 将完整组合 Release Tag 移至页脚或“数据版本”展开信息，不用长 Tag 主导首屏。
- 统计注明口径：模型家族数、适配硬件数、可下载量化模型文件数。全站总数不随筛选改变；结果区另显示匹配家族数。
- 单文件按稳定资产 ID 去重；多文件组合的文件数与规格数分别统计，不混称“模型数量”。

#### CAT-02：硬件与任务筛选

- 硬件快捷栏固定为“全部 / X3 / X5 / S100 / S100P / S600”，单选，全部为默认值。
- 详情隐藏未适配硬件，目录快捷栏始终保留五个硬件选项；某硬件没有结果时显示空结果。
- 桌面侧栏宽度 224–256 px，主要容纳任务分类和折叠的更多筛选，不重复放第二套硬件选择器。
- 任务可多选：同一维度取 OR，跨硬件／任务／关键词等维度取 AND。
- 分组使用独立维护的任务分类表。分组标签与实际任务 ID 分离，不能按中文标签或名称关键词临时判断。
- 选择父组等价于选择其全部实际子任务；部分选中显示中间态。未归类任务进入“其他任务”，不丢失。
- 当前任务 ID 全量归组后再上线；“多模态”“视觉”等分组不改变原有 Detect／Seg／Pose／Cls 的语义。
- “更多筛选”保留模型格式、量化类型、Benchmark 覆盖条件；只有一个值时弱化或隐藏该筛选控件。
- 已选条件以可移除标签显示，并提供“清空筛选”。移除单个条件不重置其他条件。

#### CAT-03：搜索与排序

- 搜索位于结果区顶部，支持模型家族名、别名、规格名和任务词。
- 已选择硬件时，规格搜索、任务和 Benchmark 条件均只匹配当前硬件的数据。
- 默认按稳定的模型名称顺序。只有存在明确维护的推荐规则时，才允许提供“推荐优先”。
- 本轮目录不提供跨家族的通用“最佳精度／最高 FPS”排名；旧数字排序深链归一到名称排序，不静默改变筛选条件。
- 数字排序放到详情页可比的规格表内；不同指标或测试条件不能混排。
- 详情按选定数值列排序时，只比较当前硬件、任务、测试配置下相同指标／单位／线程数的精确值，缺失值置后。上下界或近似值保留原始标记，不伪装成精确排名；没有可比条件时禁用该列排序并解释原因。

#### CAT-04：模型家族卡片

卡片自上而下固定为：效果图 → 家族名称 → 一句话简介 → 任务标签 → 规格摘要 → 已适配硬件 → 查看模型。

- 图片比例建议 16:9，使用仓库中经过核对的样例效果图；记录来源及使用条件。缺图使用统一的任务图形占位，不使用无关图片充当模型输出。
- 图片仅用于表达模型用途，不作为性能或精度证明。已有图中包含指标时也不能替代表格数据。
- 卡片标题显示 YOLOv8、MobileNet 等清晰家族名；标题允许两行，不直接把很长的样例目录名当作主要名称。
- 简介最多两行，规格摘要最多两行；更多规格用“共 N 种规格”承载，详情页显示完整列表。
- 未选硬件时展示家族规格去重摘要和已适配硬件；选定硬件后规格摘要限定为该硬件。
- 不放来自任意一个规格的裸 FPS、裸延迟或裸精度。数据覆盖提示如“有性能记录”必须有当前范围内的记录支撑，不能暗示所有规格已测。
- 不以当前日期充当模型更新时间。只有有来源的内容更新时间才显示。
- 卡片标题为可新标签打开的原生链接；主体点击进入同一详情；硬件按钮进入该硬件详情，点击不能触发两次跳转。

```text

X3     X5     S100     S100P     S600             ← 仅显示已适配硬件

┌────────┬────────┬─ 1 线程 ─┬─ 2 线程 ─┬─ 精度对比 ──────────┬──────┐
│ 规格   │ 输入   │延迟│ FPS │延迟│ FPS │浮点│量化│保持率      │下载  │
│ N      │ H × W  │    │     │    │     │    │    │            │.bin  │
│ S      │ H × W  │    │     │    │     │    │    │            │.bin  │
└────────┴────────┴────┴─────┴────┴─────┴────┴────┴────────────┴──────┘
每行展开：测试条件 · 其他原始指标 · 文件列表 · Benchmark 来源
```

#### DET-01：首屏与导航

- 保留独立详情页。桌面介绍区以文字为主，图片最大约 240×150 px；没有合适图片时省略，不保留空白占位。
- 不使用占据大半屏的详情 Hero。1440×900、默认字体与缩放条件下，应同时看见名称、硬件、任务、表头和至少两条规格数据。
- 顶部提供返回目录、复制当前选择链接、样例代码。不存在明确规格选择时，顶部“下载模型”只能滚动到规格表，不能任意下载第一个规格；推荐直接保留行内下载。
- 硬件条可随页面滚动吸顶；切换硬件同步切换任务、规格、指标、文件和来源。
- 默认使用目录传入的硬件；没有有效参数时按 X3、X5、S100、S100P、S600 选首个已适配硬件。
- 任务选择沿用下拉框；仅一个任务时展示静态任务标签。默认优先目标检测，否则使用固定任务顺序中的首个实际支持项。

#### DET-02：一条规格行与性能列

- 主行身份是“家族＋任务＋规格＋输入配置＋硬件＋量化产物／明确文件组合”。名称相同但输入尺寸或量化产物不同，必须有可区分的行。
- 每个线程数用两个横向子列：延迟、FPS。单位放在表头；不把 1 线程延迟与 2 线程 FPS 配在一起。
- 1／2 线程优先展示；原表存在的 4／8 等线程仍须完整提供，可通过“更多线程”展开额外列，状态写入页面状态。展开不能把数值移动到另一规格。
- 未记录线程数的指标另设“线程数未记录”列组，不归入 1 线程。
- 同一产物的准确率记录与性能记录即使来自不同原始表，也应归入同一行；前提是明确关联到相同产物和可兼容输入，而不是按名称相似度猜测。
- 默认主表展示有来源的 BPU 推理口径。同一规格的 CPU 后处理等辅助口径放在行展开区，保留原始指标与单位，不为了辅助口径重复整条主行。
- 若某任务只有端到端或后处理指标，表格标题及列头直接标出实际口径，不冒充推理性能。若需要比较多个有效口径，用显式“测试口径”选择器，不能在同一列混用。
- 不同系统、运行库、功耗模式或其他条件下的多套结果，通过“测试配置”区分；不得以 `find()` 取第一条记录掩盖其余结果。

#### DET-03：精度对照与保持率

- 固定三列：浮点精度、量化／BPU 精度、保持率。只有原表明确浮点格式为 FP32 时才标 FP32，否则使用“浮点精度”。
- 同一表的公共数据集和主指标在表格上方说明；各数值格不重复长指标名。
- 多个有效指标以明确标签对应展示，例如 Top-1、Top-5；检测与分割指标不能混写成无说明的“精度”。
- 原表给出保持率时保留其数值和有效小数；原表只有 94% 则显示 94%，不强制补零。
- 仅在相同指标、数据集、产物及可比评测条件下允许计算 `量化精度 ÷ 浮点精度 × 100%`，在展开信息中标明为计算值。
- 分母为零或条件不匹配显示“不可比较”；MAE、RMSE、WER、CER 等误差／损失指标不能套用越高越好的保持率公式，没有原文定义时显示“不适用”。
- ratio 形式的准确率可转百分数，必须保留原始值和原始单位以便核对。余弦相似度等验证指标保留其名称，不伪装成任务精度。
- 精度提高导致保持率超过 100% 时不截断，也不错误标为异常。

#### DET-04：下载与来源

- 下载按钮与对应规格同一行，短标签如“下载 .bin”；完整文件名、格式、输入要求、文件大小及校验值放在展开区，仅展示已有记录。
- 多文件运行组合以“下载文件（N）”展开明确清单；不伪造 ZIP 地址，不将同一家族的不同规格混成一套文件。
- 暂无直接地址但有真实下载说明时显示“查看下载说明”；两者都没有时显示“下载地址未记录”，不出现看似可点的假按钮。
- 展开区链接到对应样例与 Benchmark 的准确路径、提交或 Tag，并显示测试条件。分割任务不能继承检测目录链接。
- 只有经过验证的当前硬件产物出现在当前硬件下载列。任何命名修正、URL 修正均留在数据层的审核记录中，不在 UI 拼接猜测。

## 4. 视觉规范与响应式

### 4.1 视觉方向

保留 RDK 橙色为主要操作色，使用中性背景、清晰边界与轻量阴影。默认主题继续跟随系统，并保留浅色／深色切换。深色版可借鉴参考站的层次，但不把亮蓝色替换成第二套主品牌色。

| 项目 | 建议规格 |
| --- | --- |
| 页面宽度 | 最大 1440 px；桌面边距 24–32 px；手机 16 px |
| 间距 | 4／8／12／16／24／32 px 统一刻度 |
| 正文 | 14–16 px；辅助说明 12–13 px；不用极小字隐藏重要条件 |
| 标题 | 目录 32–36 px，详情 32–40 px；模型卡片 18–20 px |
| 圆角 | 卡片 12–16 px；控件 8 px；避免所有元素都做大胶囊 |
| 强调色 | 沿用现有 RDK 橙色变量，深色模式另设可读文本色；颜色值作为设计 token 管理 |
| 表格 | 数字等宽、同列对齐；规格列左对齐；合适的行分隔和 hover，高亮不承担唯一语义 |
| 状态 | 普通未测状态使用中性文字，不用大面积警告色；真正加载失败才使用错误样式 |
| 图像 | 卡片统一比例、懒加载并预留尺寸；来源图不被裁掉关键模型效果 |

### 4.2 断点行为

| 宽度 | 目录 | 详情 |
| --- | --- | --- |
| ≥1200 px | 固定宽度侧栏＋三列卡片 | 完整表格，规格列固定；尽可能首屏显示主要列 |
| 900–1199 px | 侧栏＋两列卡片 | 表格局部横向滚动，保留清晰滚动提示 |
| 600–899 px | 筛选抽屉＋两列卡片 | 硬件栏可横向滚动，表格独立滚动 |
| <600 px | 筛选抽屉＋单列卡片 | 控件换行；保持表格比较能力，不把每个数值拆成独立大卡片 |

手机筛选抽屉包含“应用”和“重置”，关闭未应用的抽屉不改变结果。硬件快捷栏在抽屉外仍可见。表格固定规格列在窄屏限制到约 112–136 px，不能遮住全部数值；必要时允许用户取消固定。

页面主体不得横向溢出。键盘焦点、Tab 语义、表格分组表头、图片替代文本和控件标签均须可用。展开表格行详情使用紧随主行、跨全表宽度的内容区域，避免把宽大详情表塞入最右侧窄单元格。

## 5. 框架与组件边界

### 5.1 保留的技术基础

沿用静态 TypeScript＋Vite＋现有 Vitest/jsdom 测试与 GitHub Pages；无需数据库或运行时服务。采用下面的单向数据流：

```text
原始 README／Benchmark 表／模型文件索引
            ↓ 数据 Agent 核验与结构化
受版本管理的目录源数据＋来源索引＋审计报告
            ↓ 构建期 schema、关联及覆盖校验
规范化 catalog + 模型详情数据 + 内容版本标识
            ↓ 只读数据加载／旧格式适配
页面状态与查询 → 列表／详情 ViewModel → 组件渲染
```

模型家族合并、硬件别名、规格解析和文件匹配属于数据构建／兼容适配层。UI 不解析文件名来猜模型身份，不从显示字符串推导任务和平台，不修改原始测试值。

### 5.2 组件拆分建议

下列名称为目标模块边界，不要求为了目录树机械拆文件。禁止为此次改版引入与页面无关的抽象层。

| 模块 | 职责与输入 | 不负责 |
| --- | --- | --- |
| `AppShell` | 顶栏、页脚、主题、语言、页面容器 | 模型排序和 Benchmark 配对 |
| `CatalogPage` | 接收 CatalogViewModel 和查询状态，组合目录 | 手写模型数据 |
| `HardwareFilter` | 五种硬件和全部，单选事件 | 根据分支名推断适配 |
| `TaskFilterPanel` | 分类树、多选条件、移动端草稿状态 | 从中文文案反推 task ID |
| `ModelFamilyCard` | 缩略图、名称、简介、规格摘要、硬件链接 | 计算全家族最佳性能 |
| `ModelDetailPage` | 当前 family/hardware/task/config 的页面组合 | 直接遍历所有源表进行关联 |
| `HardwareTabs` / `TaskSelector` | 有效选项、当前选择、键盘行为 | 将未适配项补成可选项 |
| `VariantBenchmarkTable` | 分组列、主行、展开行、局部滚动 | 选择有利的测试结果或猜下载 |
| `AccuracyComparison` | 已匹配精度、保持率及状态格式化 | 跨数据集强行计算 |
| `ArtifactDownloads` | 当前产物及明确文件组合 | 生成未验证的远端路径 |
| `EvidenceDetails` | 条件、其他指标、原始位置 | 重新解释原表数值 |
| `CatalogRepository` | 数据加载、缓存、格式版本、可见错误状态 | DOM 渲染 |
| `PageState` / `ViewModelBuilder` | URL 解析、可用选择归一化、渲染所需数据 | 获取远端模型文件 |

当前 `model-details.ts` 同时承担页面结构、指标格式、文件详情和多个交互，应按上述边界拆分。现有 `metric-display.ts`、`navigation.ts`、`query.ts` 的有效行为复用；不要在新组件中再实现一套不一致的保持率或路由逻辑。

### 5.3 数据契约

首轮兼容现有 `Catalog`、`ModelRecord`、`ModelVariant`、`BenchmarkRecord`。新增结构经适配层输出统一 ViewModel，不能要求 UI Agent 等全部数据刷新结束才开始。

| 对象 | 必需身份／内容 | 可选但不能伪造的内容 |
| --- | --- | --- |
| 模型家族 | 稳定 `familyId`、名称、任务集合、规格集合 | 简介、别名、封面、图片来源、内容更新时间 |
| 模型规格 | 稳定 `variantId`、`familyId`、task ID、规格显示名 | 参数量、计算量；必须有来源和单位 |
| 运行产物 | 稳定 `artifactId`、hardware ID、规格身份、输入配置、格式 | 下载 URL、SHA-256、实际文件字节数、文件组合 |
| 测试配置 | 稳定 `configurationId`、硬件、输入、测试口径 | OS、运行库、工具链、频率、核心数、批量、功耗模式 |
| 测量记录 | 稳定记录 ID、产物／规格的明确关联、指标名、值、单位、来源 | 线程数、统计量、上下界／近似标记、数据集及版本、浮点／量化阶段 |
| 来源位置 | 仓库、固定 ref/commit、文件路径、标题／表标识、原始行定位 | 原文片段、抓取／核验时间、校正说明 |

要求：

- 缺失数值使用缺失状态，不用 `0`、空字符串或 `NaN` 顶替；不能把“未知”变为一个默认的线程数。
- 明确区分规格大小 N/S/M/L/X、输入尺寸 H×W、参数量、模型文件大小；列名不能统称“模型尺寸”。
- 输入维度按明确布局解释；NHWC 与 NCHW 不可统一取最后两维。
- 当前 `variants` 已同时包含硬件和文件关联；迁移为更细对象时必须有稳定映射，不在此轮破坏已有链接。
- 保持率同时保留原始值、展示值及来源类型 `reported/derived`；派生值不覆盖原始测量。
- 对运行必需的多文件组合建立显式 `artifactGroupId`，不能把同目录文件默认全部归组。
- 汇总统计、目录过滤和详情下载必须调用同一个可展示资产选择规则；不能在构建与 UI 各自统计不同的文件集合。
- 数据审计状态与硬件适配状态分开。“尚未核对来源”属于维护信息，不能自动变成“尚未实测”并抹掉已有结果。

### 5.4 URL 与状态

继续使用无需服务器重写的查询参数：

```text
?model=yolov8&hardware=x5&task=object-detection
```

- 保留 `model`、`hardware`、`task` 与现有目录参数；目录任务 `catalogTask` 和详情任务 `task` 分开。
- 硬件／任务／测试配置切换写入历史；文字搜索替换当前目录状态，避免每输入一个字符产生一个后退步骤。
- 增加测试配置时使用独立 `config` 参数；未知配置回退到真实可用配置并更新 URL。
- “更多线程”展开使用 `threads=all`；缺省仅展示优先列组，其他原始线程记录仍可通过展开访问。
- 返回目录恢复关键词、筛选、分页或滚动位置和原卡片焦点；从外部直接进入详情时返回默认目录。
- 不在浏览器端伪造 `/models/...` 路径导致 Pages 刷新 404。将来变更路由必须单独设计旧链接兼容。

### 5.5 数据加载与版本一致性

- 数据必须由构建产物提供，不在用户浏览时抓取 GitHub README 或逐个请求模型下载服务器。
- 目录先加载轻量家族信息；详情数据可按家族延迟加载，但拆分不是首个 UI 原型的前置条件。
- 正式拆分时入口索引记录 `schema_version`、内容版本和详情文件名；详情文件使用内容哈希或同批次版本名，禁止把两个构建批次混装。
- 新页面兼容仍可能被缓存的上一版数据结构；不兼容时提供清晰重试提示，不显示半套错误指标。
- 加载状态、空结果、未知模型、请求失败、格式不支持分别处理。单个家族的非致命审计问题不应让全部目录崩溃；涉及错误指标或文件关联时在构建期阻止发布。
- 错误日志保留实际失败原因，用户界面使用简明文案。不得吞掉所有异常后只留下无法诊断的“加载失败”。

## 6. Benchmark 数据刷新 Agent 的交接要求

本节定义后续数据工作的交付边界，不表示本轮已经重新逐表核验。UI Agent 使用当前已知数据与覆盖边界的测试样例；数据 Agent 提供刷新结果，两者通过第 5 节契约集成。

### 6.1 逐表核验流程

1. 列出 X3、X5、S 系列所用的仓库 ref、样例目录及全部候选 Benchmark 表；记录固定 commit，不能只写会变动的分支名。
2. 逐份读取原始文件内容，包括表头、单位、脚注、测试环境和下载脚本；搜索命中列表不能替代阅读原表。
3. 为每张表和每条原始行建立可追溯索引，区分性能、精度、保持率、其他验证指标及不适用内容。
4. 保留 1／2／4／8 等真实线程信息和原始精度指标；不使用 `1000/latency` 补造 FPS，不根据相邻行补缺失值。
5. 精确映射 family、task、variant、hardware、input、artifact；歧义进入审计问题清单，不按最相近文件名自动匹配。
6. 对输入格式、文件名、目录、README 和 Benchmark 不一致的情况记录证据与处理结果。校正值与原始值并存，保留来源。
7. 去重必须保留重复出处；冲突不能用“最后读取到的值”覆盖。当前 UI 已有可信记录不得仅因新扫描未命中就静默删除。
8. 生成结构化数据、覆盖清单、变更摘要及回归样例；运行契约和生产目录加载检查。

已有 `x3-v1.0.0`、`x5-v1.0.0`、`s-v1.0.0` 不得重打。若读取新分支上的更新表格，应记录其确切源提交；刷新展示数据与改变发布版本属于不同操作。

### 6.2 必须交付的清单

| 交付物 | 必须包含 |
| --- | --- |
| 来源清单 | release line、源 commit、文件路径、表标题、表数量与处理状态 |
| 行级覆盖报告 | 原表行标识、结构化记录 ID、收录／重复出处／非 Benchmark／排除／冲突等结论及原因 |
| 关联报告 | 规格、输入、硬件与量化文件的映射；无法确定的关系单独列出 |
| 差异报告 | 新增、纠正、保留、删除的记录，以及每项删除／改值依据 |
| 可消费数据 | 符合约定 schema 的目录／详情数据，不含 UI 专用 HTML |
| 回归样例 | 多线程、不同数据集、同名不同尺寸、未测可下载、多文件组合、未知线程、误差指标等边界 |

覆盖验收要求每个候选原表行都有处理结论，而不是要求每行都变成展示数值。数据冲突清单和审计中间状态供维护者使用，不作为额外产品后台加入本轮 UI。

## 7. UI／框架 Agent 的执行顺序

| 阶段 | 工作 | 交付与退出条件 |
| --- | --- | --- |
| A：页面骨架 | AppShell、目录两栏布局、硬件栏、卡片、独立详情布局 | 使用明确标注的演示数据完成桌面／手机设计预览；不将演示指标写入生产数据。 |
| B：组件与状态 | 拆详情表、下载和来源模块；统一 URL、筛选、统计及数据适配 | 现有家族与硬件规则不回退；刷新、返回、任务切换正常。 |
| C：数据接入 | 接入数据 Agent 的规范化结果 | 所有展示值和文件可追溯；歧义不能变成可下载按钮或虚假数值。 |
| D：整体验收 | 真实目录端到端检查、响应式与键盘验证、构建与发布检查 | 通过下一节验收；记录上线版本与公网验证证据。 |

UI Agent 不必等待全部 Benchmark 整理完成才做 A/B，但 C/D 必须使用完整真实目录验证。数据 Agent 不修改 CSS、页面 DOM 或在显示组件内补模型特例。共享 schema 的变更先同步到双方的契约测试，不能各自新增同名异义字段。

## 8. 验收标准

### 8.1 产品与交互

- [ ] 目录首屏可见硬件快捷栏、搜索入口和至少一排模型卡片，统计与长 Release Tag 不挤占主要浏览区。
- [ ] 卡片具有一致的图片、标题、简介、规格与硬件层级；无图时占位正常，长标题不破坏对齐。
- [ ] YOLOv8 各大小共用详情，YOLOv9 独立；MobileNet 版本聚合正确，带 MobileNet 骨干的其他模型不被误并。
- [ ] 目录固定五种硬件；详情仅显示已适配硬件；未测但可运行的文件仍可访问。
- [ ] 同规格的延迟／FPS／精度／保持率／下载可同行定位，切硬件后不残留上一硬件数据。
- [ ] 1／2 线程横向对照；更多线程可完整访问；CPU 后处理与 BPU 口径明确分开。
- [ ] Top-1／Top-5、检测／分割 mAP 不混淆；缺值、不可比较和不适用具有不同文案。
- [ ] 下载定位到正确量化产物，ONNX 不出现在下载入口或可下载文件统计中。
- [ ] 任务切换同步更新正确样例与原表来源。
- [ ] 深链、刷新、前进后退、返回目录恢复、原生新标签打开均可用。

### 8.2 工程与数据

- [ ] 运行现有 `npm run check`；新增验收覆盖实际 bug 风险，不只验证组件能创建。
- [ ] 必须用构建出的完整生产目录装载目录页和代表详情页，不能只测手写 fixture。重点覆盖统计、筛选、来源和文件关联。
- [ ] 统计与可展示资产采用同一规则，避免再次出现生成端按量化文件计数、UI 按全部文件校验而导致整站加载失败。
- [ ] 页面组件中没有新的模型名／文件名正则特例或复制的指标常量。
- [ ] 1440、1024、768、390 px 截图检查；主页面无水平溢出；390 px 的表格仍能定位规格、滚动查看数据和下载。
- [ ] 浅色、深色、中英文、键盘切换和焦点恢复均检查；触控控件不依赖 hover 才可发现。
- [ ] 部署产物的数据与 UI 格式版本匹配；公网分别验证目录、X5 已测详情、S100P/S600 未测可下载详情、X3 来源与口径。
- [ ] 源表覆盖报告可证明逐表逐行完成，任何改值和删除均可解释；没有额外板卡测试或伪造测试结果。
