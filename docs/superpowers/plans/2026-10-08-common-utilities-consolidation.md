# 公共目录统一方案

状态：待实施的目录方案。本次 ResNet 注释修正不搬迁全仓依赖。

## 目标布局

根目录只维护一套公共库 `utils/`，不再同时维护 `samples/_shared/`。

```text
utils/
├── py_utils/     # Python SDK 封装、图像、标签、张量、分类等公共函数
└── c_utils/      # C/C++ 公共头文件与实现、板卡身份等能力
tools/           # 可独立执行的下载、校准、批量评估等维护工具
samples/         # Sample 本身的模型逻辑、入口、转换、评估和测试
```

公共目录按语言区分，内部按完整职责组织模块，不为每个函数建文件。
模型专属的解码与配置留在对应 Sample，多 Sample 复用的任务辅助按实际消费者核查。

## 当前需要处理的内容

- `samples/_shared` 提供当前 Sample 使用的 SDK 会话、制品绑定、图像、标签等能力。
- `utils/py_utils` 保留图像、后处理、文件与可视化函数；与 `_shared/image.py` 等存在职责重叠。
- C++ 公共代码同时存在于 `samples/_shared/cpp/c_utils` 和 `utils/c_utils`。
  当前检查发现 12 个头文件/源码逐字相同，README 不同；执行搬迁时需重新核查，
  确保搬迁前新增的修复不会丢失。
- `utils/tools` 是独立程序，应归入现有根目录 `tools`。
- 两个 Python 目录的导入时机不同。现有 `utils/py_utils/__init__.py` 会导入可视化模块，
  合并时必须保留 CLI 帮助、列表、dry-run 不导入 NumPy/OpenCV/板端 SDK 的行为。

## 实施顺序

1. 列出 Python 导入、资源定位、测试 patch 目标、CMake/include 路径及文档引用。
2. 对重复函数比较输入输出、插值、NV12 排列、量化和错误处理，确定唯一实现。
3. 将公共能力移入 `utils/py_utils`、`utils/c_utils`，让包初始化保持轻量。
4. 同步更新所有 Sample、工具和测试的引用及相对资源根定位；维护工具移入 `tools`。
5. 更新当前架构规范、README、源码文档配置与命令示例。历史记录中的旧路径按历史保留。
6. 删除 `_shared` 和重复实现，不留下第二套可执行兼容目录；接口迁移说明单独保存。

## 验收

- 活跃代码、测试、构建和使用文档不再依赖旧公共目录。
- 公共模块与全部受影响 Sample 的主机测试通过；静态契约检查通过。
- CLI 帮助/模型列表/dry-run 保持无需 SDK，错误板卡仍在 SDK 加载前拦截。
- 关键张量、NV12 字节和模型后处理结果与搬迁前一致。
- C++ include/CMake 路径及适用主机构建检查通过；板端 SDK 执行另记实际结果。
- 不更改模型导出/编译配方，不修改 ACT/Pi0 上游子模块。
