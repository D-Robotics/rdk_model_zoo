## 范围与验收

仍只做 YOLO 目标检测、ResNet 分类和一个 PaddleOCR 样例。减少样例数量不减少所选样例的完整部署流程。原 Spec 的 D02/D03/D05/D07/R20 继续适用。

- [x] 各样例按实际源文件收敛导出、转换、评估和运行实现；相同算法一个维护位置。
- [x] 不等价实现局部保留，记录输入输出和保留原因；不复制两套完整平台目录冒充合并。
- [x] 旧入口仅做参数、默认值、路径和返回格式适配；不维持第二套等价算法。
- [x] 中英文 README 从使用者任务组织：环境、准备、执行、结果、程序接口、源码阅读、转换评估与排错。
- [x] Conversion 给出已有链路的输入、导出、校准、编译、产物及运行衔接；缺失上游步骤明确说明，不编造已验证命令。
- [x] 公共 NV12 转换收敛，保留任务特定缩放和错误边界；主机与受影响板卡回归。
- [x] 独立检查源码去重、路径/导入、文档命令及回归证据；不以测试数替代结构验收。

## 执行分工

按已采用的 subagent-driven-development 流程，将 ResNet、OCR、YOLO 的互不重叠样例交由三个实现者处理；负责人串行维护公共图像转换、根 README、样例导航与板测，最终审查每个实现。

共同基线是 `cd74a2b241075bb21036d8d0855d0403f8e8c963`；已有未提交实现全部保留并增量修订。禁止提交、推送、发布和变更系统 SDK。模型身份与既有清单不改写。

## 已核实缺口

1. ResNet/OCR Conversion 与 evaluator 只有旧目录链接；不构成完整的规范化 Sample。
2. 根 README 混合“首批 YOLO”“分类试点”“全部完成”等多轮追加说明，缺少统一任务导航。
3. 三个 Sample 重复维护完全相同的 OpenCV I420 转 NV12 平面算法；只应将这一等价操作共享，不能顺便统一任务缩放。
4. 旧目录仍有真实算法，需要逐文件检查可执行兼容与唯一维护位置，而非仅保证新入口可运行。
